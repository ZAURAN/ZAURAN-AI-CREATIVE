# SaaS, UI и продуктовые ролики

## Выбери тип демонстрации

Различай достоверную демонстрацию существующего продукта, стилизованный launch film и концепт будущего интерфейса. Для первого важна точность поведения; для второго можно упрощать представление, сохраняя правду о функции; третий явно обозначается концептом.

Основа: **задача пользователя → действие → ответ системы → полезный результат**. Выбери один основной сценарий для короткого ролика. Несколько функций связывай общей целью, а не галереей плавающих окон.

Неизвестные функции, цены, сроки, интеграции, метрики и отзывы не выдумывать. При отсутствии скриншотов можно сделать сценарный черновик с явно условными UI-состояниями и перечнем нужных экранов. Не выдавать его за точную демонстрацию продукта. URL, скриншот и запись — разные уровни доступности информации.

## Состояния и непрерывность

Для каждого экрана зафиксируй ID, выбранный объект/вкладку, введённые данные, состояние процесса, результат. Между сценами сохраняй ID документа, имя проекта, выделение и значения, если действие их не меняло.

Для взаимодействия: курсор подходит → наводится (если важно) → один клик/ввод → UI реагирует → результат получает время для чтения. Курсор не вызывает событие до попадания в цель; после действия не закрывает важную информацию. Тач-жесты и мышь не смешивать без причины. Нажатие, loading, success и error показывать только там, где они нужны сценарию.

Сокращённая обработка — монтажное решение, не обещание фактической скорости продукта. Не использовать фейковые перманентно растущие графики или фиктивные «100%» как доказательство качества.

## Постановка UI

- Сначала дать ориентир: где находится нужный элемент. Затем приблизить деталь по смыслу; показать достаточный контекст до следующего действия.
- На мобильном выходе не пытаться уместить и прочитать весь desktop dashboard. Выбрать релевантную область или разрешённую упрощённую композицию.
- Указать слои, которые нужно реконструировать отдельно: окно, текст, кнопка, курсор, график, ответ системы. Скриншот не позволяет независимо анимировать внутренние элементы без подготовки.
- Кроп, маска и масштабирование не меняют логики интерфейса. Перестановка контролов и удаление блоков — стилизация, которую нужно обозначить.
- Приближение 2D-прекомпа обычно достаточно для обзора UI; 3D-сцена нужна, только если ракурс/параллакс несёт смысл. Учитывать разрешение скриншотов при увеличении.
- Синхронизировать VO с видимым доказательством: функция появляется в тот момент, когда о ней говорят; не показывать другой экран во время объяснения.

Для ролика можно предложить цепочку: задача → ключевое действие → раскрытие результата → бренд/CTA. Длительности выбирай после оценки конкретного интерфейса и текста, а не универсальные «по 2 секунды на экран».

Проверка: зритель понимает, что сделал пользователь и что получил; каждый переход имеет причинное основание; нет невозможных кликов и выдуманных возможностей; UI читаем на целевом размере; показанные данные допустимы для публикации и при необходимости заменены согласованными демонстрационными.
