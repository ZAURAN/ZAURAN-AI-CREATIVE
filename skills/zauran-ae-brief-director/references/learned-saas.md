# SaaS: библиотека постановочных решений

Это адаптируемые схемы, не готовые шаблоны и не измеренные настройки оригиналов. ID ведут к первичным ссылкам/охвату в `studies/saas.md`. Выбирай по коммуникационной задаче; конкретные тексты, цифры и тайминг назначай текущему продукту.

## S1. Запрос → действие → доказательство

Опора: jX4dLxiso6A, FtNWrBUOJ24. Для AI-функции показать содержательный запрос, цель клика, реакцию компонента, обработку, читаемую выдачу. Крупный план кнопки мотивирует смену состояния. В ТЗ перечислить точные входные данные и ожидаемый результат, отделить движение камеры от изменения UI, закончить паузой чтения. Не переносить рекламные метрики. AE-вариант: раздельные прекомпы поля/кнопки/результата с общей системой координат; способ реализации предложенный.

## S2. Сохраняемый prompt через варианты

Опора: _PLSHdVR4no. Для демонстрации изменения дизайна сохранить одно поле ввода как визуальный якорь, а результат позади менять согласно запросу. В ТЗ назвать, что сохраняет позицию, что перестраивается и что подтверждает выполненную команду. Случайная смена цветов не доказывает смену структуры. Для перехода можно использовать перекрытие, маску или склейку, не обещая автоматически точный morph.

## S3. Одна карточка → несколько результатов

Опора: SgmuplXU2iY. Контекст библиотеки → выделение материала → вынос карточки → несколько осмысленно разных версий → возврат в UI. Назначить связь каждой копии с результатом функции (например, язык), сохранив идентичность исходного материала. Уточнить, сколько копий, где их подписи, что остаётся главным. Не размножать карточки только для заполнения кадра.

## S4. Навигация как каркас нескольких функций

Опора: ksnHSIngptY. Фиксированное место тезиса и выделяемый пункт навигации связывают разные разделы продукта. Для каждой функции — отдельный читаемый фрагмент, а полный dashboard служит контекстом. ТЗ включает последовательность разделов, выделение, доказательство пользы и возврат ориентира. Если ролик короткий, выбрать одну задачу вместо ускоренной экскурсии по всем экранам.

## S5. Формы и соответствующая выдача

Опора: POZ8qiJDEiI. Показать критерий поиска и значимые изменения формы, затем результат, соответствующий выбранным данным. В ТЗ перечислить значения before/after, порядок полей, положение курсора и момент перевода фокуса. Не менять чекбоксы до клика и не использовать абстрактные товары при конкретном запросе. Lifestyle-вставка возможна как контекст потребности.

## S6. Пространственная витрина продукта

Опора: aSte18D2_YE, luoDI5Bo0w0, hszNZTElIzE. Один крупный интерфейс/устройство и подчинённые карточки создают иерархию. ТЗ задаёт главный объект, степень читаемости спутников, границы наклона/кропа и смысл выносимых данных. Наклон не требует полноценного 3D: возможны 2.5D-прекомпы. После насыщенной сцены разгрузить финал до бренда и одного действия.

## S7. Брендовая система вместо UI-demo

Опора: k3d_xeVxEOE. Последовательность «геометрия → буквы → знак → цвет → применение» подходит, когда задача — идентичность. В ТЗ задаётся соответствие форм между состояниями и контраст масштаба. Не выдумывать клики/функции ради слова SaaS. Типографическая сцена и showcase допустимы, но их не называть демонстрацией работающей функции.

## Обязательные поля для выбранной схемы

Режим сцены (demo/showcase/метафора/бренд), главный объект, исходное состояние, действие, ответ, текст/данные, время на результат, сохраняемый объект на стыке. Упрощение UI помечается стилизацией. Точное значение длительности выбирается после оценки текущего текста, а не копируется из референса.
