# Шаблон задания на озвучку

Это проектный документ, **не API payload**. Для короткого ответа оставь текст, голос/подачу и настройки. Неизвестное помечай явно; не заполняй фиктивными ID или измерениями. Скобки ниже — поля шаблона, не TTS-теги.

```markdown
# VOICE — [проект / сцена / версия]

Источник: [точный SCRIPT/VO и версия либо текст пользователя]
Область: [исходные ID сцены, шота, требования]
Режим: [точное следование / границы разрешённой правки]
Результат: [только текст / генерация / монтаж]
Модель и среда: [имя и реальный model ID; UI/API/хост]
Язык: [язык, нужный акцент]
Голос: [CHAR_ID; название; voice ID или «не выбран»]
Клон/референс: [версия, источник если применимо]
Исполнение: [адресат → цель → тактика → смена намерения]
Длительность: [целевое окно; оценка; факт после измерения]
Настройки: [поддерживаемые поля и значения/«по текущему UI»]
Разрешённые запуски: [объём из поручения / синтез не заказан]

## SOURCE_TEXT
[дословный текст]

## Произношение
| Исходник | Произносимая форма / IPA / alias | Основание | Проверено на голосе |
|---|---|---|---|

## SPOKEN_TEXT
[полный ожидаемый слышимый текст]

## TTS_TEXT
[полный текст для копирования; без служебных заголовков внутри поля]

## Дубли
| Take / файл | Model / voice | Настройки / контекст | Что изменено | Фактическая длительность | QA |
|---|---|---|---|---|---|

## Передача в видео
[dry master, таймкоды, необходимость lip-sync, открытые ограничения]

## Проверка
| Критерий / ID | Файл и интервал | Наблюдение | Статус |
|---|---|---|---|

## Итог
[подготовлено / сгенерировано / проверено / принято — раздельно]
```

При просьбе «перепиши промпт» возвращай полный TTS_TEXT новой версии. Для диалога каждый блок привязан к говорящему средствами хоста. Пользователь не должен собирать итог из нескольких сообщений.
