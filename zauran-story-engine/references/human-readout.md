# Один READOUT для человека

## Когда нужен

В производственном пакете и при явной просьбе о PDF собери один READOUT_<проект>_vN.pdf. Быстрые идеи, аудит, локальная правка/разбивка, ответ в чате и запрос только промпта по умолчанию не требуют PDF или новых файлов. Применяй границу выдачи из `../../references/story-production-contract.md`; название производственного этапа само по себе не включает пакет.

При продолжении сохранённого проекта сохраняй выбранный режим выдачи, включая существующий пакет. Последняя явная просьба пользователя о кратком ответе/работе только в чате меняет объём текущей выдачи без повторного согласования; если PDF не обновлён, не называй прежний актуальным.

Канонический путь текущего READOUT берётся из живого STATE и существующей структуры проекта/эпизода. Если путь ещё не выбран, назначь его внутри этой структуры и запиши в STATE. Копия PDF в handoff — архивный снимок с указанием канонического пути и версии; она не становится вторым текущим READOUT. Пример команды ниже иллюстративен и не переносит PDF в корень при уже назначенном пути.

Для каждой сохранённой версии сценария в режиме пакета собери соответствующий PDF. Даже правка одного шота создаёт новую версию. В режиме разработки PDF можно отложить; STATE должен явно показывать, к какой версии относится последний PDF. Устаревший PDF не называй актуальным.

## Содержание

Включай только существующие и нужные разделы, обычно в таком порядке:

1. Обложка: проект, версия, дата, черновик / на утверждение / утверждён.
2. Краткий концепт и бриф.
3. Биты с таймингом, если разработаны.
4. Полный актуальный сценарий.
5. Речь, если вынесена отдельно.
6. План эпизодов, если это часть запроса.
7. Открытые решения и материалы от заказчика.
8. Короткое ТЗ на производство, если пакет готовится для него: источник и версия, важные обязательства, открытые блокировки и ссылка на актуальную трассировку из STATE.

Не добавляй пустые главы. Сценарий должен читаться без открытия служебных файлов. Персонажи могут быть обозначены именами и краткой легендой; полные паспорта остаются в handoff. Язык — по запросу пользователя. Не выдумывай лимит генераций или свойства модели.

READOUT помогает человеку прочитать пакет; он не заменяет точные исходники, промпты или проверку дублей. Статусы в нём соответствуют единой трассировке, без отдельной схемы: план и корректный текст промпта не доказывают исполнение в результате.

## Сборка

Пути файлов и скрипта разреши относительно их фактических папок. Передай точный упорядоченный список актуальных файлов, не маску SCRIPT_*.md.

```text
python "<skill-root>/scripts/build-readout.py" --out "<project>/READOUT_project_v2.pdf" --title "Проект — v2" --subtitle "На утверждение" "<project>/STORY_LOCK.md" "<project>/SCRIPT_v2.md"
```

Зависимости: Python с пакетом markdown и Chrome/Edge/Chromium. При необходимости выбери браузер через --browser "<path>"; --timeout задаёт предел ожидания в секундах (по умолчанию 60). Сначала проверь доступные зависимости среды. При ошибке не выдавай ссылку на несуществующий PDF: сохрани Markdown и назови конкретный сбой; если PDF был частью запроса, работа над ним ещё не закончена.

Сборщик экранирует служебный текст, ограничивает HTML и блокирует внешние ресурсы; изображения показывает подписью. Это текстовый сценарный READOUT, а не портфолио со встроенными картинками. Для PDF с изображениями нужен отдельный явно выбранный документный маршрут.

Существующий PDF не перезаписывается. Выбери новую версию; для повторного экспорта того же сценария после исправления вёрстки — суффикс export2 и запиши его в STATE. Не удаляй старый файл для обхода защиты.

На файловых системах с жёсткими ссылками готовый PDF публикуется атомарно. Где ссылки не поддерживаются, используется копирование с исключительным созданием: перезаписи нет, но файл виден во время копирования. Ссылку пользователю выдавай только после успешного завершения скрипта.

## Проверка выдачи

Скрипт проверяет создание нового PDF; этого недостаточно для проверки вёрстки. Открой или отрендери PDF доступными средствами и проверь кириллицу, таблицы и отсутствие обрезанного текста. Сверь версию и разделы с исходниками. Если визуальная проверка недоступна, скажи об этом, не заявляй её выполненной.

В ответе с пакетом первая ссылка — READOUT. Другие рабочие файлы — по необходимости; пользователь может читать Markdown, если предпочитает его. Не делай отдельный PDF на каждый служебный файл.
