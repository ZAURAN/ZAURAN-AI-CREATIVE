# Хранилище, версии и продолжение

Применяется к сохранённому проекту и производственному пакету. Быстрые ответы и аудит скилла не требуют STATE, папок или журналов.

## Путь и существующий проект

1. Используй назначенную пользователем папку или путь из STATE. Для нового сохраняемого проекта без назначенного пути спроси его один раз; не задерживай независимую работу над текстом.
2. Ищи STATE / _STORY_ROOT только в текущей проектной или названной папке. Не сканируй дом, диск или чужие проекты.
3. Если STATE нет, но есть сценарии/канон, прочитай относящиеся к запросу файлы и восстанови индекс из свидетельств. Не называй проект новым автоматически.
4. Корень = папка со STATE. Папка эпизода может быть отдельно: запиши её путь в реестре, добавь _STORY_ROOT.md со ссылкой на корень. Следуй только явной ссылке на проект.
5. В папке с монтажом и футажами используй story/, не перемещай чужие файлы. Производные папки episodes/E01 допустимы внутри уже назначенного корня; отдельный путь спрашивай только если его действительно нужно выбрать.

## Минимальные файлы

```text
<корень>/
  STATE.md                 — индекс, указатели версий, состояние утверждённого мира
  STORY_LOCK.md            — бриф и допущения
  CANON.md                 — если есть общие правила мира
  TIMELINE.md              — если накапливаются события или нужен план сезона
  characters/PASSPORT_<имя>.md
  episodes/E01/            — либо отдельная зарегистрированная папка
    BEATS.md
    SCRIPT_v1.md
    SCRIPT_v2.md
    VO_v2.md               — если речь вынесена отдельно
    READOUT_<проект>_v2.pdf — для пакета
    REFERENCES.md
    handoff/
  NOTES.md                 — решения и существенные уроки
  production/              — при переходе от сценария к визуальным материалам
    ASSET_PLAN.md          — выбранные карточки, порядок, открытые вопросы
    ASSET_REGISTER.md      — ID, состояния, источники, версии и зависимости
    SHOT_TRACE.md          — трассировка нескольких шотов, если нужна на этом этапе
    assets/<ID>/           — CARD_vN.md, PROMPT_<ID>_vN.md и реальные файлы по мере работы
```

Для одиночного ролика биты и сценарий лежат в корне. Не создавай пустые CANON, TIMELINE и паспорта ради дерева. Для самостоятельной серии может быть только каталог эпизодов; антологии не нужен общий мир, если его нет по замыслу.

Production создаётся только при соответствующем этапе; существующие пути из STATE переиспользуются. Общий протокол карточек — `../../references/script-to-assets.md`. Живой STATE остаётся единым для обоих скиллов; STATE внутри handoff является снимком, а не отдельной текущей версией.

Сквозную трассировку веди по `../../references/story-production-contract.md`: для одного шота — в существующей записи PROMPT, для нескольких — в `production/SHOT_TRACE.md` или уже принятом эквиваленте. Не создавай второй реестр с конкурирующими статусами; в STATE держи один актуальный указатель. Быстрые запросы допускают ту же проверку в чате без новых файлов.

## STATE

```md
# STATE — [Проект]
Обновлено: YYYY-MM-DD HH:MM
- Режим: разработка / производственный пакет
- Связь эпизодов: сквозной сюжет / самостоятельные / антология / одиночный
- В работе: [эпизод, этап]
- Последний черновик: [точный путь и версия]
- Последний утверждённый сценарий: [точный путь; кем/когда или «нет»]
- Актуальный READOUT: [единственный канонический путь и версия сценария; либо «не собран»; копии handoff — снимки]
- Утверждённые CANON/паспорта: [версии и пути]
- Следующий шаг: [...]
- План/реестр визуальных материалов: [пути; источник SCRIPT и статус, если этап начат]
- Выбранные элементы и актуальные промпты/изображения: [ID, версии, пути; либо «не выбраны»]
- Реестр требований: [путь/раздел; точный источник, версия и область ID]
- Трассировка шотов: [единственный актуальный путь/раздел PROMPT или SHOT_TRACE; либо «этап не начат»]

## Состояние утверждённого мира
- Место/время, отношения, знания, реквизит: [...]
- Необратимые последствия: [...]
- Открытые нити: [...]
- Для самостоятельных выпусков — правила накопления/сброса: [...]

## Реестр путей
| Что | Абсолютный путь | Основание | Дата |
|---|---|---|---|
| Корень | [...] | пользователь | [...] |
| E01 | [...] | внутри назначенного корня / пользователь | [...] |

## Открытые решения
- [...]
```

Черновик не сдвигает утверждённое состояние мира. Укажи его отдельно. Переход в канон — после явного утверждения соответствующего содержания.

## TIMELINE

```md
# TIMELINE — [Проект]
## Утверждённые события
| Время мира | Событие | Эпизод и версия | Кто знает | Последствие |
|---|---|---|---|---|

## План (FLEX)
| Эпизод | Функция | Рабочее событие | Открытая нить | Статус |
|---|---|---|---|---|

## Ограничения порядка
- [...]
```

Утверждение сценария связывает событие с точной версией; не смешивай предложенное с произошедшим. В самостоятельной серии отслеживай только выбранные накопительные факты.

## Продолжение

Прочитай STATE, указанный актуальный черновик или утверждённый сценарий по задаче, нужные части CANON/паспортов, связанные события TIMELINE и последние существенные решения NOTES. Не загружай всю историю сезона для правки одной реплики.

При следующем эпизоде кратко сообщи, откуда продолжаем, что известно, какие нити и ограничения актуальны. Для сквозного сюжета проверь последствия; для самостоятельного — инварианты и правила сброса; для антологии — обещание формата. Буквальный стык первого и последнего кадров нужен лишь по замыслу. Различай знания зрителя и персонажей: персонаж может знать то, что зрителю ещё не раскрыто.

Явная новая правка пользователя имеет приоритет над старым файлом. Зафиксируй её без повторного подтверждения. Если непонятно, это новая версия канона или гипотетический вариант, уточни конкретную развилку.

## Версии и реестр требований

- Каждая сохранённая выдача или правка SCRIPT = новый SCRIPT_vN.md; старую не переписывай. Технические промежуточные правки до выдачи не требуют отдельных версий.
- Перед правкой прочитай точный актуальный файл по STATE; при отсутствии указателя сравни версии численно, не лексикографически (v10 позже v9). При разных ветках без ясного основания не угадывай.
- CANON, паспорта и BEATS имеют версию в заголовке; перед заменой сохрани предыдущую под версионным именем в ARCHIVE/, сохраняя рабочий путь. Не архивируй перемещением файл, на который ещё ссылаются.
- Сохраняй нетронутые блоки дословно, если их не затрагивает новая правка. Проверь связанные биты, тайминг, речь и continuity; неизбежные зависимые изменения включи в отчёт.
- Изменения записывай в порядке: новая версия → зависимые документы → STATE с точными указателями. При сбое укажи, что осталось несогласованным; не объявляй пакет завершённым.
- Изменённые требования, камера или функция шота требуют пересверки связанных раскадровок, промптов и дублей. Их прежние проверки помечай stale по общему контракту до повторного просмотра; старые доказательства сохраняй с исходной версией, не переноси pass на новую автоматически.
- NOTES фиксирует существенные решения, не копирует весь сценарий. STATE обновляется после сохранённой версии/утверждения и перед завершением работы над проектом.

С v1 сохраняемого сценария веди реестр (в сценарии либо едином файле REQUIREMENTS.md, путь записан в STATE). Его ID и статусы регулирует `../../references/story-production-contract.md`. Сохраняй уже существующие R1, R2 и т. п. вместе с областью источника/эпизода/сцены/шота; не перенумеровывай весь проект при передаче или новой версии. Для сквозных доказательств используй трассировку по общему контракту, а не дополнительные независимые таблицы:

| ID | Требование | Источник (сообщение/файл/дата) | Статус | Покрытие / причина |
|---|---|---|---|---|
| R1 | [...] | явная команда | active | сцена/шот |
| R2 | [...] | явная команда | blocked | конфликт с R1; варианты решения |
| R3 | [...] | прежняя команда | removed | отменено новой явной командой; ссылка |

Гипотеза остаётся предложением, пока не принята; не добавляй её как обязательное active-требование. Несовместимость или предел инструмента не разрешают удалить, смягчить или заменить требование: blocked сохраняет обязательство и причину. Явная замена пользователем допускает removed со ссылкой на новую команду, без повторного вопроса. Пакет с blocked не готов к производству, но может быть выдан как черновик с открытыми решениями.
