# Handoff в производство (zauran-ai-creative)

Завершив сценарный этап, переходи к плану визуальных материалов по общему протоколу `../../references/script-to-assets.md`. Промты под модель, выбор модели/среды, генерация, QA — `zauran-ai-creative`. Handoff = пакет с точными версиями сценария и референсов; он запускает приём готового контекста, а не повторный бриф. Модель, среда и неразрешённые производственные условия могут потребовать уточнения перед промптами.

Приоритеты решений, статусы и сквозное соответствие «источник → раскадровка/шот → промпт → результат» определяет `../../references/story-production-contract.md`. Применяй этот контракт вручную; не дублируй его схему в handoff и не заявляй автоматическую смысловую проверку. Передача сохраняет последние разрешённые изменения пользователя и уже данное разрешение в его границах.

## Сначала план материалов

После утверждения законченного сценария видео, если пользователь не ограничил задачу только текстом, сразу составь перечень персонажей, локаций и значимых предметов, черновые спецификации карточек и рекомендуемую последовательность. Затем предложи, для каких конкретных элементов писать промпты. Готовые паспорта и изображения переиспользуй. Подробные поля, вопросы и статусы определяет общий протокол; не заводи его отдельную копию здесь.

Для этого предварительного перехода достаточно сценария со сценами. Выбор модели, камера и свет каждого шота, готовые изображения и производственный READOUT не должны блокировать анализ и инвентаризацию. Полный пакет ниже собирается при соответствующем запросе. Локальная правка, отдельный шот или промпт не требуют нового полного перечня материалов. Если соседнего протокола нет, выполни нейтральный план элементов и передай точные пути сценария; не придумывай контракт модели или запуск генерации.

## Пакет

Собирается из папки проекта (`project-vault.md`) и копируется в `episodes/EXX/handoff/` (для одиночного ролика — `story/handoff/`):

```text
handoff/
  READOUT_<проект>_vN.pdf — снимок канонического PDF по живому STATE; не для промтов
  STORY_LOCK.md          — из story-routes.md
  STATE.md               — снимок состояния на момент передачи
  CANON.md               — если мир повторяется
  PASSPORT_<имя>.md      — на повторяющихся/значимых героев; ID и версия
  BEATS.md               — бит-лист с таймингом
  SCRIPT_vN.md           — утверждённая версия шот-сценария с реестром
  VO_vN.md               — текст + режиссура (если есть речь)
  REFERENCES.md          — роли референсов (ниже)
  ASSET_PLAN.md          — снимок плана визуальных материалов, если уже создан
  ASSET_REGISTER.md      — снимок реестра элементов и зависимостей, если уже создан
  SHOT_TRACE.md          — снимок сквозной трассировки, если она ведётся отдельным файлом
```

Действующие ASSET_PLAN/ASSET_REGISTER находятся по указателям живого STATE проекта (по умолчанию в production/). Копии в handoff — только снимки со ссылкой на оригиналы. Производственный скилл обновляет живые документы, не создавая конкурирующее состояние проекта.

READOUT в handoff — копия ровно той версии, на которую ссылается передача. Её канонический путь и версия указаны в снимке STATE; живой STATE хранит единственный текущий READOUT. Копирование не создаёт новую редакцию PDF и не меняет актуальный путь.

Тот же живой STATE содержит путь реестра требований и единственный актуальный указатель трассировки: запись существующего PROMPT для одного шота либо `production/SHOT_TRACE.md` для нескольких. В снимке STATE сохрани эти пути и точные версии источников. Если промпта или дубля ещё нет, передай запланированные места и `not_checked`; не заполняй отсутствующие доказательства успехом. Быстрый handoff в чате не требует создания этого дерева или PDF.

## REFERENCES.md — контракт ролей

```md
| Файл / тег | Роль (ровно одна) | Что брать | Что НЕ переносить |
|---|---|---|---|
| @Герой_turnaround | персонаж | лицо, волосы, одежда | фон, свет |
| @Кухня_hero | локация | геометрия, материалы | людей, реквизит |
| @Грейд | стиль | палитра, контраст, зерно | архитектуру, объекты |
| @Продукт | продукт | форма, лого, цвет | руки, упаковку-соседа |
```

Один референс — одна роль. Теги — как в инструменте пользователя, `@Тег` дословно.

## Маппинг в BRIEF LOCK производственного скилла

| zauran-ai-creative ждёт | Берётся из |
|---|---|
| что делаем, формат, цель | STORY_LOCK |
| что сохранить / что изменить / что запрещено | CANON §2–3, §6; STORY_LOCK «Запрещено» |
| герой, локация, продукт | PASSPORT §A, CANON §4, §6 |
| шоты, камера, свет, звук, инварианты | SCRIPT_vN |
| роли референсов | REFERENCES.md |
| элементы, состояния, выбранные карточки и зависимости | ASSET_REGISTER / ASSET_PLAN по указателям живого STATE |
| требования, функции и решения камеры, покрытие и открытые блокировки | реестр требований и трассировка по живому STATE; единый `../../references/story-production-contract.md` |
| модель и среда генерации | **не решает этот скилл** — уточняются для модельных промптов/генерации в `intake-and-brief.md`, не блокируют анализ |

## Перед полным handoff для шот-производства

1. Director's review из `story-routes.md` пройден.
2. Каждый шот SCRIPT_vN содержит камеру (термин словаря), свет, инварианты, изменение или функцию.
3. Каждый CHAR_ID@vN разрешается в приложенный точный паспорт этой версии. Состояние сцены указано отдельно. При сборке промтов производственный скилл разворачивает §A без перефразирования, если требуется его контрактом.
4. Реестр сверен без потерь: каждое относящееся к передаче active связано с конкретным разделом/шотом, способом показа, функцией и решением камеры по общему контракту. Сохрани исходные ID и их область; blocked передай как открытые обязательства, removed — только с явной отменяющей инструкцией пользователя. При конфликте пакет остаётся черновым.
5. Трассировка содержит точные версии источников и указатель для продолжения в промптах/постпродакшене. Проверь текстовый перенос отдельно от фактического исполнения: непроверенный дубль не может получить pass; изменения источника делают затронутые прежние проверки stale. Ошибку камеры, действия или функции нельзя молча принять как новую норму.
6. Приложенные файлы и предусмотренный режимом READOUT соответствуют указанным версиям, существуют и читаются. STATE и REFERENCES содержат точные указатели; живое состояние одно. Ссылки в ответе кликабельны.

## Что не обещать

Длительность клипа, lip-sync, число референсов, физика, разрешение — свойства конкретной модели. Скилл истории пишет «шот 1 — 2 с»; сможет ли модель дать ровно 2 с — проверяет производственный скилл по своему платформенному файлу.
