# Приём сценария и готовых изображений

## Где найти соседние скиллы

Сначала используй пути, явно названные пользователем, затем каталог доступных скиллов. В этом репозитории соседние точки входа находятся относительно папки `zauran-scene-director`:

- `../SKILL.md` — zauran-ai-creative;
- `../zauran-story-engine/SKILL.md` — zauran-story-engine.

При отдельной установке найди их по именам в каталоге скиллов. Перед относительным переходом из junction/symlink разреши реальную папку. Пути к скиллам не являются корнем нового проекта.

Прочитай обе точки входа один раз при первом использовании связки. Дополнительно по задаче:

| Задача | Файл относительно владельца |
|---|---|
| Найти актуальный сценарий и продолжить | story-engine: `references/project-vault.md` |
| Разбить действие на планы | story-engine: `references/scene-to-shotlist.md` |
| Принять готовую передачу | story-engine: `references/handoff-to-production.md` |
| Найти карточки и зависимости | ai-creative: `references/script-to-assets.md` |
| Выбрать нужные производственные знания | ai-creative: `references/knowledge-routing.md` |
| Геометрия, камера и игра | ai-creative: `references/cinematic-orchestration.md`, далее его условные модули |
| Промпт финальному генератору | актуальный платформенный файл ai-creative |

Не загружай все платформенные модули для обычного поиска фотографии. Если соседний скилл отсутствует, продолжай модель-независимую постановку по доступному сценарию; сообщи о конкретном недостающем контракте, не выдумывай его.

## Обнаружение рабочего состояния

1. В названной/текущей проектной папке проверь `STATE.md`, `story/STATE.md` и `_STORY_ROOT.md`. Следуй указателям существующего проекта. Несколько проектов без ясного выбора — один вопрос о нужном проекте.
2. Прочитай выбранный SCRIPT, STORY_LOCK, относящийся CANON и паспорта, если есть. Архивный handoff не заменяет живой STATE. Для одного кадра достаточно соответствующей сцены с соседними действиями и общими ограничениями.
3. Прочитай текущие SCENE_PLAN/SHOT и ASSET_REGISTER/ASSET_PLAN/REFERENCES по указателям STATE. При их отсутствии ищи сценарии и изображения только внутри назначенных папок. Не выбирай максимальную версию автоматически.
4. Проверяй реальные файлы, когда даёшь ссылку. Более новая явная команда пользователя важнее устаревшей записи «не сгенерировано». Наличие файла без решения пользователя не доказывает утверждение.
5. Сообщи кратко: «Продолжаем [сцена/бит/шот], источник [версия]. Есть [рефы], сейчас делаем [этап]». Не заставляй повторять уже известные формат, модель и путь.

## Что передаётся между этапами

- SOURCE: путь и версия сценария; режим сохранения; сцена/бит; исходное действие; дословная речь.
- LOOK: CHAR/LOC/PROP IDs, состояния по сцене, утверждённые визуальные версии и точные пути.
- STAGING: версия площадки, камера, блокинг, контакт, последовательность движения, первый/последний кадр.
- GENERATION: модель/хост/режим; соответствие вложений ролям и тегам; запрошенный результат; активный PROMPT.
- PROGRESS: реальные файлы результатов; проверка; решение пользователя; следующий шот или зависимость.

Промпты могут разворачивать эти сведения, но не становятся новым источником канона. Не переименовывай существующие CHAR_ID при уточнении имени героя. Спорное соответствие имени и звериной формы оставь открытым до подтверждения.
