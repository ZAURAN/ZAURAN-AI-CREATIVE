# Blender: сценарий → площадка → камера → превиз

Этот маршрут выполняет ту же постановку, что `shot-and-set.md`, в редактируемом `.blend`. Фото остаются источниками внешности и материалов, простой 3D-макет управляет пространством и движением. Создавать новый сценарий для Blender не нужно.

## Доступ и фактическая проверка

При первом запуске проверь установленный Blender и его версию. В исходной среде проверены Blender 5.2.1 LTS, фоновый запуск и чтение сцены/камеры через `bpy`. Это не проверка всех будущих скриптов, рендера, рига или видеокодеков. Найди фактический executable в текущей среде и проверь `--version`.

Если путь изменился, сначала PATH, затем известная установка или реестр установленных приложений Windows. Не ищи по всему диску. Если Blender не найден, подготовь запрошенное ТЗ/скрипт и назови отсутствие среды исполнения; не объявляй сцену созданной и не устанавливай приложение без поручения.

Предпочтительные способы управления:

Проверенный вариант подключения — сторонний `ahujasid/blender-mcp` (сервер PyPI 1.9.1, аддон protocol 5), запись клиента `mcp_servers.blender`. В исходной среде проверены MCP initialize, список 28 инструментов и get_scene_info. Установка этого скилла сама не устанавливает MCP или аддон. Проверь их наличие, настройки телеметрии и соединение в текущей среде. Штатный локальный адрес проекта MCP — `127.0.0.1:9876`, но действуют настройки пользователя. Перед работой прочитай реальную открытую сцену через get_scene_info.

Этот аддон отказывается обслуживать команды в `--background`; MCP требует Blender с GUI. Прямые bpy-скрипты через background остаются отдельным рабочим маршрутом. При занятом порте определяй процесс-владелец: не запускай несколько Blender с listener на одном порту. Не закрывай несохранённую пользовательскую сцену ради переподключения.

1. Подключённый Blender-коннектор с документированными операциями — если он действительно работает с нужной сценой.
2. Локальный `blender.exe --background ... --python ...` — для воспроизводимой сборки и рендера. `bpy` исполняется внутри Blender; не устанавливай его через pip в обычный Python для обхода запуска.
3. UI — для доступной ручной проверки или действий, которые не покрывает API.

Не путай Python API облачного редактора Higgsfield с управлением локальным Blender. Изолированный background-процесс не видит несохранённые изменения открытого Blender. Если пользователь поручил изменить именно открытую сцену, используй рабочее подключение к ней или согласованный сохранённый исходник.

## Вход и файлы результата

Прими SCRIPT/SHOT, выбранные референсы, текущий SET и формат из проекта. Для порученной сборки сохраняй рядом с постановкой:

- `build_<scene>_vN.py` — воспроизводимый bpy-скрипт;
- `SET_<scene>_vN.blend` — редактируемая площадка с персонажами и камерами;
- `renders/<shot>/...png` — проверочные кадры и, при заказе, последовательность;
- `PREVIS_<shot>_vN.mp4` — только после фактического успешного экспорта/кодирования;
- краткие пути и статусы в текущем SHOT/SCENE_PLAN, указатель в живом STATE.

Не создавай все эти файлы для запроса «только промпт». `.blend` — рабочий проект; Seedance получает поддерживаемый медиафайл, а не автоматически этот проект. GLB/FBX экспортируй только если он нужен выбранному следующему инструменту, не как обязательную часть видеопроизводства.

## Сборка через bpy

1. Для новой площадки запускай отдельный процесс с `--factory-startup`, очищая только его временную стартовую сцену. Для существующего проекта загружай явно выбранный `.blend` и сохраняй новую версию. Не выполняй глобальный select-all/delete в пользовательской сцене. Новые объекты группируй по сцене в коллекции, а повторный запуск обновляет только принадлежащие скрипту объекты по ID.
2. Используй коллекции `SET`, `CHARACTERS`, `PROPS`, `CAMERAS`, `LIGHTS`, `REFERENCES`. Реестровые CHAR/PROP IDs перенеси в имена и custom properties. У каждого персонажа собственный root; дети и риг должны принадлежать ему. Один актёр не получает анимацию другого по совпадению цвета или имени материала.
3. Масштаб — метры, Z вверх; различай мировые и локальные оси. Создай пол/воду, стеновые объёмы, проёмы и необходимую мебель. Сверь пропорции по утверждённым ориентирам. Отсутствующий задний вид фото — повод отметить достроение, а не выдавать реконструкцию за точную.
4. Персонажи для блокинга — нейтральные манекены с читаемым направлением головы и корпуса. Простой иерархический манекен подходит для поворота/жеста; для походки, сложных суставов и контакта нужен соответствующий риг или доступная разрешённая модель. Не обещай готовую фотореалистичную голову из одного портрета. Фото можно держать как viewport-reference с выключенным render visibility.
5. Назначь отдельную камеру каждому шоту, установи `scene.camera`, разрешение и процент рендера, fps и диапазон кадров. Камера Blender смотрит вдоль локальной −Z, локальный Y служит верхом; target-ориентацию вычисляй явно. Указывай sensor fit/sensor size вместе с lens или используй FOV. Проверяй кадр из камеры: перспектива пользовательского viewport не равна финальной.
6. Ключи ставь по определённому таймингу на конкретные объекты/кости. Движение root, жесты и камера — раздельные каналы. Перевод секунд в кадры учитывает fps/fps_base; проверяй включённые границы диапазона. Для равномерного движения подходит linear, для начала/остановки — контролируемое ускорение. Проверяй overshoot и удержание конечной позы. Используй API анимации установленной версии, не предполагай старую структуру Actions/fcurves.
7. Реквизит привязывай к нужной руке/кости или target в нужный момент; при смене родителя сохраняй мировое положение. Проверь стопы на опоре, кисть на предмете, отсутствие проникновения тела в мебель. Левитация — заданная траектория root; брызги и магия не обязательны для геометрического превиза.
8. Добавь достаточный для чтения формы свет. Движок выбирай из реально доступных: быстрый Eevee/Workbench для макета, Cycles лишь при нужной задаче. Не вводи универсальные лимиты полигонов, текстур или обязательные web-оптимизации для киношного превиза.
9. Сохрани `.blend` в новую версию, затем отрендери начало, важный контакт/середину и конец. Сначала проверь несколько кадров, потом запускай запрошенный полный рендер. Для чистого превиза исключи надписи, оси, вспомогательные объекты и UI. Для человека отдельный технический обзор может их показывать.

Скрипт должен выдавать ошибку при отсутствии нужного входа/объекта и возвращать ненулевой код через `--python-exit-code`. Не проглатывай исключения и не сохраняй полусобранную сцену как готовую. Параметры, меняющиеся между шотами, держи в явном блоке конфигурации или уже существующем проектном manifest.

## Запуск и экспорт

PowerShell вызывает проверенный executable через `&` и отдельные аргументы. Путь со spaces — один аргумент. Пример формы команды, где переменные предварительно заполнены проверенными абсолютными путями:

```powershell
& $blenderExe --background --factory-startup --python-exit-code 1 --python $buildScript
```

Для исходного `.blend` вместо `--factory-startup` передай его путь до запуска скрипта. Порядок аргументов Blender влияет на выполнение; рендер запускай после загрузки сцены и настроек. Для фонового запуска отдельным `Start-Process` используй скрытое окно, если пользователь не просил открыть интерфейс.

Надёжный промежуточный выход — PNG-последовательность. MP4 делай через доступный в установленной версии видеовыход Blender или проверенный FFmpeg. Не предполагай наличие `FFMPEG` среди image formats во всех версиях. При внешнем кодировании сохрани исходную последовательность, частоту кадров, порядок и итоговую длительность; проверь файл инструментом медиаинспекции и визуально. Не объявляй H.264/MP4 готовым по одному расширению имени.

## Передача и проверка

- Проверяй реальные сцены/камеры и ключи, а не только успешное завершение Python. Существующий `.blend` и корректный exit code необходимы, но не доказывают правильный кадр.
- Просмотри начало, конец, контакты и движение, если был создан клип. Проверь композицию, роли героев, направление взгляда, край кадра, геометрию и continuity.
- Сохрани точный файл превиза и выбранные фото. Роли: превиз — пространство/камера/движение; фото — лицо, костюм, внешний вид окружения. Проверяй поддержку режима video-reference у целевого хоста через `zauran-ai-creative`.
- Если результат не удалось просмотреть, пометь его как созданный, но непроверенный. При ошибке исправляй конкретную причину и не повторяй бесконечно тяжёлый рендер.

Официальные справочники для актуальных API и CLI: https://docs.blender.org/api/current/ и https://docs.blender.org/manual/en/latest/advanced/command_line/ . На дату добавления модуля веб-доступ к ним не сработал; локальные version checks и bpy-интроспекция остаются проверяемым источником для установленной версии.
