### Mandatory model gate before any prompt

- Root cause fixed: "Какая модель или сервис используется?" was one of four questions inside the delivery group, so a prompt could be written or adapted before the target model was fixed — and a prompt is always model-specific (block order, reference-binding syntax, limits, field format all differ).
- Added "Гейт выбора модели" to `references/intake-and-brief.md`: ask before writing, rewriting, or adapting any prompt unless the model is already named, in `BRIEF LOCK`, in the latest `PROMPT_vN.md`, or implied by the request. Ask as one question with options, narrowed to the image group (Nano Banana Pro, GPT Image, Seedream 5.0) or the video group (Seedance 2.5, Seedance 2.0, MiniMax H3, Gemini Omni Flash), recommended option first with a one-line reason tied to the actual task. Includes what each model is strong at and which contract file it loads.
- "Adapt my prompt" with no model named is the same gate: ask which model to adapt to; infer the source model from the prompt's own structure and ask about it only when it changes the result.
- After the answer: record model and environment in `BRIEF LOCK` and in the `PROMPT_vN.md` header, load that model's contract, then write. A mid-task model switch rebuilds reference binding, block order and limits, and the change is reported.
- Exemptions: no prompt in the deliverable (pure idea, concept, shot list, storyboard) skips the gate entirely; fast-edit mode narrows it to a single question asked only when the model is genuinely unknown, since an edit cannot run without one.
- Mirrored in `SKILL.md` (fast-edit exception, section 2 hard rule, section 6 Nano Banana Pro execution rule) and `references/knowledge-routing.md` (own Nano Banana Pro block).

- Held-out gate: no existing file overwritten or deleted; the `seedance-2.0` package, GPT Image, Seedream 5.0, Seedance 2.5, MiniMax H3, Gemini Omni Flash contracts and the YouMind library are untouched. All three earlier test suites still pass alongside the new one.

## 2026-08-27 — Lossless prompt iteration (requirement ledger)

- Root cause fixed: on iterative edits the skill silently dropped both old and newly added requirements, because "Правило полной выдачи промпта" allowed the model to delete anything it judged "conflicting", the full prompt was regenerated from chat memory each round, and long-chat context compaction erased earlier versions.
- Rewrote "Правило полной выдачи промпта" in `SKILL.md`: numbered requirement ledger (`R1…`, source, `active | removed`), user edits ADD by default, removal only on explicit user cancellation or a named physical conflict, never silent weakening of negatives or small details.
- Added a lossless-rebuild contract: echo the understood edit in one paragraph before rebuilding (no blocking wait when unambiguous), copy untouched blocks verbatim without paraphrasing, verify every `active` requirement against the assembled prompt, and report added / changed / removed / unchanged after each edit.
- Added prompt versioning on disk: canonical prompt plus ledger saved to `PROMPT_vN.md` in the project folder; each iteration starts from the latest file, not from chat memory. Mirrored in the `qa-and-delivery.md` iteration checklist.
- Scoped the stale-fragment cleanup rule in `cinematic-orchestration.md` to tags and fragments of OTHER shots only, and protected user-added or previously confirmed negatives from the "keep the negative list short" trim.
- `intake-and-brief.md` iteration rule now points to the ledger and requires the pre-rebuild echo.
- Held-out gate: fast-edit mode, routing, platform contracts (Seedance 2.5, MiniMax H3, GPT Image, Seedream 5.0) and QA flow are unchanged; only the iteration/rewrite discipline was touched.
