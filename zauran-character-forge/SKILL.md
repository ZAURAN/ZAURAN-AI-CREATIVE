# zauran-character-forge

Модель по умолчанию выдаёт самое вероятное: Элара со шрамом, кожаная куртка, погибшие родители. Этот скилл уводит от среднего. Случайные зацепки, противоречие, конкретика, проверка на штампы. Персонаж = поведение + силуэт + одежда, которая рассказывает биографию.

## Связь со скиллами

- `zauran-story-engine` владеет сценарием, каноном и форматом паспорта: `../zauran-story-engine/references/character-passport.md`. Этот скилл заполняет паспорт, формат не меняет.
- `zauran-ai-creative` владеет выбором модели, промптами и генерацией: turnaround, лист костюма, карточки.
- `zauran-context-guard` переносит предложенные теги при сжатии чата.

Если персонаж уже есть в готовом сценарии клиента, факты сценария не меняй. Придумывай только открытые признаки и помечай их как предложение. Правила точного следования — в `zauran-story-engine`.

## 1. Режим

| Режим | Когда | Результат |
|---|---|---|
| Быстрый | «придумай персонажа», идея в чате | 8 питчей → 3 концепта, без файлов |
| Полный | герой для проекта | паспорт + одежда + теги |
| Каст | 2+ персонажа вместе | как полный + проверка различимости |
| По сценарию | герои уже названы в сценарии | только открытые признаки, факты сценария LOCKED |

Не раздувай быстрый запрос до полного пакета.

## 2. Бриф

Нужно знать: функция персонажа в истории, жанр и тон, формат (реклама, серия, фильм, картинка), мир, эпоха и место, визуальный стиль (фото, аниме, 3D, стилизация), ограничения (бренд, возраст аудитории), что уже зафиксировано.

Извлеки известное из чата и файлов. Спроси не больше 1–3 вопросов о критичном. Остальное предположи и назови предположение одной строкой. Не спрашивай о том, что решат зацепки.

## 3. Зацепки

Модель выбирает самое вероятное, отсюда штампы. Поэтому сначала случайность. Тяни по этапам: все категории сразу дают шум и спорящие зацепки.

```bash
node <папка скилла>/scripts/draw-character-seeds.mjs --stage concept --count 8
```

- `--stage concept` — занятие, противоречие, талисман, тайна. Для людей.
- `--stage concept-any` — плюс природа персонажа: предмет, погода, день недели, животное, чувство в теле. Для рекламы, маскотов, анимации, если бриф не требует человека.
- `--stage look` — форма, силуэт, палитра, материал, эпоха, пластика, привычка. Тяни на шаге 6–7, когда концепт уже выбран.
- `--seed N` повторяет результат.

Без Node: попроси пользователя назвать числа и возьми пункты по номерам из `references/character-seeds.json`, либо честно скажи, что выбрал вручную наименее очевидные.

Зацепки — искра, не требование. Оставь зацепку, если она создаёт напряжение с брифом. Замени, если противоречит миру или брифу. Покажи пользователю, какие зацепки использованы.

## 4. Мозговой штурм: сначала много, потом отбор

**Шаг 1. Восемь питчей.** Один набор зацепок — один питч в одну строку. Каждый питч опирается хотя бы на одну зацепку и отвечает на бриф. Не отбрасывай странные питчи на этом шаге: странное часто лучшее.

**Шаг 2. Отбор трёх.** Оцени каждый питч по четырём вопросам:
- свежесть: не из списка `references/anti-cliche.md`, не первое, что пришло бы в голову;
- попадание: работает на бриф, жанр и формат;
- картинка: силуэт и цвет видны сразу;
- сцены: из персонажа сами рождаются действия и конфликты.

Три лучших должны различаться по разным осям: природа, занятие, противоречие, форма, возраст, тон. Не три вариации одного.

**Шаг 3. Три концепта**, каждый 5–7 строк:

- **Питч за 2 секунды.**
- **Противоречие:** две черты, которые обычно не встречаются вместе.
- **Одна странная вещь** и одна черта, доведённая до предела.
- **Хочет прямо сейчас** и что мешает.
- **Силуэт одной фразой** + основной цвет.
- **Зацепки:** какие использованы.

Под концептами дай оставшиеся пять питчей одной строкой каждый: пользователь может выбрать любой.

Рекомендуй один концепт первым и объясни выбор одной фразой по брифу. В полном режиме дождись выбора, если пользователь заранее не сказал «делай сам».

**Шаг 4. Смешать и докрутить.** Предложи пользователю два действия одной строкой:
- **смешать:** взять черту из одного концепта и одежду или тайну из другого — «A + костюм из B»;
- **ручки:** страннее / приземлённее, смешнее / мрачнее, моложе / старше, человечнее / сказочнее. Поворот ручки меняет одну ось, остальное сохраняется.

Новый раунд по запросу «ещё»: новые зацепки с новым seed, прошлые питчи не повторяй.

## 5. Ядро

Для выбранного концепта заполни паспорт §C–F. Методы — `references/character-methods.md`, часть 1:

- призрак → ложь → хочет → нуждается; ложь объясняет хотя бы одно видимое поведение;
- три ползунка: активность, симпатия, компетентность — что высоко, что растёт;
- вид слабости: недостаток, самоограничение или внешнее ограничение;
- 2–3 конкретные повторяющиеся черты: привычка, фраза, предмет — видимые в кадре;
- в касте каждый противостоит герою по-своему (Труби, ссылка в `character-methods.md`).

Для рекламы и маскота глубокая психология не нужна: поведение, пластика, внешность.

## 6. Внешность

По `references/character-methods.md`, часть 2. Для идей внешности и одежды вытяни `--stage look --count 1`, если форма, силуэт и палитра ещё не заданы брифом:

- форма силуэта + один акцент другой формы;
- 2–3 метки силуэта, узнаваемые в чёрной заливке;
- палитра 60/30/10; в касте у каждого свой основной цвет;
- лицо не по среднему: 2–3 конкретные черты, возраст числом, те же слова во всех промптах;
- пластика: как стоит, как ходит;
- имя по брифу имени (часть 3), проверено по `references/anti-cliche.md`.

Внешность пиши в паспорт §A (LOCKED) и §B (FLEX).

## 7. Одежда

По `references/costume-design.md`:

- ответь на вопросы биографии: кто купил, когда, для чего, что показывает и прячет, что не на месте;
- собери слои: база, средний, верхний, аксессуары — по работе, погоде и статусу;
- опиши каждую вещь формулой: материал + фактура + посадка + конструктивная деталь + состояние;
- карта износа: где и почему вещь стёрта, чем починена;
- талисман: один предмет, связанный с раной или целью;
- если есть сюжет — арка гардероба: что меняется и в какой сцене;
- если сцены известны — план костюмов по сценам;
- **WARDROBE LOCK:** одна строка с дословным описанием основного наряда для всех промптов.

Узнаваемость клади в силуэт и крупные цветовые зоны, не в логотипы и мелкий принт: они плывут между генерациями. Реальные бренды не используй.

## 8. Проверки перед выдачей

1. **Штампы:** пройди `references/anti-cliche.md`. Каждое совпадение замени или оправдай одной фразой.
2. **Видимость:** каждый важный факт прошлого виден в одежде, теле, предмете или поведении — либо явно помечен как скрытый до раскрытия.
3. **Каст:** тест трёх слов, своя метка силуэта, свой основной цвет, разные телосложение, форма и стойка.
4. **Сценарий клиента:** факты не изменены, предложения помечены.
5. **Культура:** реальная культура — конкретная среда, а не костюм для вечеринки. Непроверенную деталь назови непроверенной.

## 9. Выдача

- **Быстрый режим:** восемь питчей, три концепта и рекомендация в чате.
- **Полный режим:** `characters/PASSPORT_<имя>.md` по шаблону story-engine. Основной наряд — в §A (LOCKED), варианты — в §B (FLEX). Если нарядов несколько или есть план по сценам — `characters/COSTUME_<имя>.md`, путь в §G. Папку проекта бери из STATE или спроси один раз. Без папки — выдай паспорт в чате.
- **Теги:** предложи `@Тег` для персонажа и для каждого наряда и предмета, который пойдёт референсом. Если пользователь уже назвал теги — бери его написание дословно, с пробелами и кириллицей. Новый тег делай коротким; одно написание везде. Статус «предложен», пока пользователь не назначил тег в интерфейсе. Запиши в §G.
- **Картинки:** передай §A, WARDROBE LOCK и теги в `zauran-ai-creative` для turnaround и листа костюма. Модель и среду выясняет он. Промпт без модели не пиши, генерацию без запроса не запускай.

В конце одна строка: следующий шаг — например, «делаем turnaround» или «придумываем второго персонажа каста».
