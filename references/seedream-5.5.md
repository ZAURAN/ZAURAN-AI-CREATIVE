# Seedream 5.5 — рабочая инструкция

Обязательный файл, когда генерация или редактирование изображения идет на **Seedream 5.5** (ByteDance Seed, релиз 2026-11-09; Volcano Ark называет модель `Doubao-Seedream-5.5`, Dreamina — «Image 5.5»). Файл владеет параметрами, лимитами, маршрутами, многошаговой правкой, прозрачным выводом и диагностикой именно для 5.5.

Ремесло промпта наследуется из `seedream-5.md`: порядок блоков (раздел 2), паттерны сборки (3), грамматика правки и preserve-списки (4), роли референсов и identity block (5), текст и верстка (7). Читай эти разделы как базу. Числа, лимиты, model ID и наборы контролов 5.0 Pro / Lite на 5.5 **не переносятся**, и наоборот. При конфликте с `seedream-5.md` по 5.5 побеждает этот файл.

Не применяй файл к видео и к другим image-моделям. **Seedream 5.5 Pro** анонсирован, но не вышел (на 2026-11-11): не обещай его и не переноси на него этот файл без проверки.

## 2. Среда — уточни до сборки промпта

От среды зависят контролы прозрачности, число референсов, разрешение и наличие отдельного режима слоев. Спроси одним вопросом, если среда не ясна из чата.

| Среда | Что известно |
| --- | --- |
| Jimeng (即梦) web | 创作 → 生成 / 画布 → Seedream 5.5 |
| Doubao app/web, Doubao Work | 图像生成 → Seedream 5.5; в Doubao Work — 技能 → Seedream5.5 |
| Volcano Ark, центр опыта | 视觉模型 → 图片生成 → `Doubao-Seedream-5.5`; строка API в таблицах моделей на 2026-11-11 отсутствует |
| BytePlus | Playground по ссылке из официального блога; callable model ID не найден |
| Dreamina / CapCut | Страница модели есть, доступ «when available»; в UI — соотношение сторон, разрешение, число выходов, прозрачный вывод |
| Picsart (AI Playground) | 1K / 1.5K / 2K; 1:1, 4:3, 3:4, 16:9, 9:16, 3:2, 2:3, 21:9; до 10 исходных изображений; negative prompt есть; Background: Auto / Transparent / Opaque |
| Kie.ai (API, async `POST /api/v1/jobs/createTask`) | ID хоста: `seedream/5-5-text-to-image`, `seedream/5-5-image-to-image`, `seedream/5-5-layer-decomposition`; поля ниже |

Kie.ai — поля хоста, не официальная схема ByteDance:

- text-to-image: `prompt` 5–5000 символов, `aspect_ratio` (список как у Picsart), `size` `1K | 1.5K | 2K` (дефолт 2K), `output_format` `png | jpeg`, `background` `auto | transparent | opaque` (transparent требует png), 1 изображение на запрос.
- image-to-image: `image_urls` 1–10 публичных URL (JPEG/PNG/WEBP, до 10 МБ), `aspect_ratio` плюс `auto`, остальное как выше.
- layer-decomposition: см. раздел 6.

Не придумывай официальный ID вида `doubao-seedream-5-5-…` или `dola-seedream-5-5-…`. Для API на Ark / ModelArk бери ID только из списка моделей в консоли пользователя; на 5.0 префиксы у площадок разные (`doubao-…` на Ark, `dola-…` на BytePlus). Seed, маска, отдельное поле guidance на 5.5 не подтверждены ни на одном хосте — не предлагай их, пока не увидишь в интерфейсе.

**Формат локаций 21:9** из SKILL.md на 5.5 выполним: 21:9 есть в списках Picsart и Kie.ai. В других средах проверь список соотношений.

**Разрешение:** подтверждено до 2K. Запрос 4K — честно скажи, что у 5.5 не подтвержден, и предложи upscale отдельным шагом. Слово `4K` в промпте разрешение не меняет.

## 3. Когда выбирать 5.5, а когда остаться на 5.0

Выбирай 5.5, когда задача опирается на его заявленные сильные стороны:

- длинная цепочка локальных правок одного изображения (интерьер, образ персонажа, предметка, интерфейс, циферблат, иллюстрация);
- прозрачные ассеты: стикеры, леттеринг, иконки, вырезанный продукт, элементы для композитинга, стекло, дым, перья;
- плотный мелкий текст (газета, инфографика, упаковка) — с обязательной вычиткой;
- фотореализм кожи, материалов и естественного света.

Оставайся на модели, где уже утверждена серия (5.0 Pro, Lite или другая): смена модели посреди серии меняет почерк. Не переключай молча — предложи пользователю и зафиксируй решение в `BRIEF LOCK`. Если у хоста пользователя 5.5 еще нет — работай на 5.0 по `seedream-5.md`.

## 4. Форма промпта

Промпт по-прежнему на английском (общее правило навыка). Порядок — из `seedream-5.md`: `subject → setting → composition → lighting → style/medium → constraints`. Особенности 5.5 по официальным примерам на странице проекта:

- **Соотношение сторон в тексте и в настройке.** Официальные примеры пишут формат прямо в промпте: `Use a 16:9 landscape format`, `vertical 3:4 street photograph`. Выставляй тот же формат контролом хоста; текст его не заменяет.
- **Геометрия и графика числами.** Примеры задают точные элементы: `thin 3 px dark gray border`, `tilted about 25 degrees clockwise`. Числовые детали допустимы для рамок, наклона, позиций.
- **Фотографический характер одной-двумя подсказками**: пленка, ракурс, тип съемки (`Fujifilm Provia colors and film grain`). Без списков тегов качества.
- **Реализм без глянца.** 5.5 по умолчанию гасит пересвет и избыточный блеск. Не добавляй `glossy`, `HDR`, `ultra-detailed`, `perfect skin` по инерции. Нужен глянец — назови поверхность и источник блика явно.
- **Текст** — дословно в кавычках, с местом, ролью, поверхностью и начертанием: `the word "Seedream 5.5" in rounded, bold sans-serif letters`.

```text
Vertical 3:4 street photograph of a cyclist in a mustard rain jacket waiting at a crosswalk in light drizzle, shot from a low angle with the camera tilted about 25 degrees clockwise. Wet asphalt reflects red traffic lights; overcast evening light with a soft glow from a shop window on the left. Natural skin texture, realistic fabric with water beads, no excessive gloss. Fujifilm Provia colors and fine film grain. No text or logos.
```

## 5. Многошаговая правка (до 100 раундов)

Главная новая возможность. Заявленная пиксельная стабильность не отменяет протокол: каждый раунд проверяется.

**Протокол цепочки:**

1. **Раунд 0 — база.** Утвержденное изображение. Сохрани файл как `R00`.
2. **Одна правка — один раунд.** Короткая повелительная инструкция: что меняется, где, и строка сохранения. Не смешивай локальную правку со сменой стиля, света или кропа в одном раунде.
3. **Вход раунда N+1 = выход раунда N.** Так устроена официальная демо-цепочка. Не возвращайся к исходнику без причины: потеряешь накопленные правки.
4. **Не переописывай весь кадр.** Полное описание сцены провоцирует перерисовку. Описывай только изменение плюс короткий preserve-список (грамматика — `seedream-5.md`, раздел 4).
5. **Строка согласованности** для правок, затрагивающих пространство: `while maintaining coherent perspective, occlusion, lighting, and cast shadows` — так сформулированы официальные примеры.
6. **Журнал раундов.** Веди `EDIT_LOG.md` рядом с `PROMPT_vN.md`: номер раунда, точная инструкция, файл результата, итог проверки дрейфа. Промпт каждого раунда — короткая правка, а не новая версия общего промпта; версию `PROMPT_vN.md` повышай, когда меняется сама задача или база.
7. **Контрольная точка каждые ~10 раундов** или после крупной правки: визуальная сверка с `R00` по лицу, логотипу, тексту, палитре, перспективе.
8. **Дрейф найден — откат.** Вернись к последнему чистому раунду и повтори правку с адресной защитой. Не наслаивай исправления поверх испорченного раунда.

```text
Change only the armchair by the window: replace its grey upholstery with deep green velvet. Keep the room layout, every other object, wall colour, camera angle, and daylight direction unchanged, while maintaining coherent perspective, occlusion, lighting, and cast shadows.
```

```text
Move the cardboard box from the floor onto the wooden bench on the right. Keep everything else unchanged, while maintaining coherent perspective, occlusion, lighting, and cast shadows.
```

**Проверка неизменности пикселей.** Заявление «pixel-level» не измерено публично — проверяй сам, если размеры раундов совпадают. Рамка изменений должна лежать в зоне правки:

```bash
python -c "import sys;from PIL import Image,ImageChops;a,b=(Image.open(p).convert('RGBA') for p in sys.argv[1:3]);print(a.size==b.size and ImageChops.difference(a,b).getbbox(alpha_only=False))" R07.png R08.png
```

Вывод — `(x1, y1, x2, y2)` области изменений, `None` — изменений нет, `False` — размеры разные (хост пересэмплировал; тогда сверяй визуально). Рамка заметно шире зоны правки — дрейф, откат к прошлому раунду. Хост может перекодировать JPEG и дать шум по всему кадру: для цепочек бери PNG.

## 6. Прозрачные ассеты (RGBA)

**Сначала контрол, потом текст.** Если хост дает `background: transparent` или переключатель Transparent — включи его и выбери PNG. JPEG альфу не хранит никогда. Если контрола нет, официальные примеры просят прозрачность фразой в промпте.

Официальные формулировки со страницы проекта:

- `with a transparent background` — объект или персонаж целиком;
- `transparent outside the lettering` — леттеринг и логотипы;
- `Keep the background transparent outside the sticker elements` — набор стикеров;
- `output it as a separate RGBA layer with a transparent background` — извлечь объект из сцены;
- `each on a separate layer` — серия элементов.

**Полупрозрачность** (заявлена официально): назови, какие части частично прозрачны и насколько — стекло, дым, вуаль, пряди волос, перья, тень. Тень на прозрачном фоне — тоже полупрозрачная область: реши, нужна ли она.

```text
A clear glass perfume bottle with a pale amber liquid and a brushed silver cap, three-quarter product view, soft studio light from the left creating a gentle highlight along the glass. The glass and liquid are semi-transparent, so the background shows through them; the cap is fully opaque. No cast shadow, no floor, no text. Fully transparent background outside the bottle.
```

**Нельзя:** слова `checkerboard`, `transparency grid`, `PNG background` — модель может нарисовать фальшивую шахматку. Белый или шахматный фон на картинке — не прозрачность.

**Проверка альфы обязательна** до статуса «готово»:

```bash
python -c "import sys;from PIL import Image;im=Image.open(sys.argv[1]);print(im.mode, im.getchannel('A').getextrema() if 'A' in im.getbands() else 'NO ALPHA')" asset.png
```

Ожидание: режим `RGBA` или `LA`, минимум альфы `0` (есть прозрачные пиксели); для полупрозрачных ассетов — значения между 0 и 255 в нужных зонах. Затем положи ассет на темный и на светлый фон и проверь края: ореол, бахрома, остатки фона. `NO ALPHA` или минимум `255` — прозрачности нет: включи контрол хоста или PNG, затем повтори.

## 7. Разделение на слои (функция хоста)

Официальный блог описывает RGBA, но **не** отдельный режим декомпозиции. Декомпозиция есть у хостов как отдельная модель: Kie.ai `seedream/5-5-layer-decomposition` (Atlas Cloud упоминается вторично, не проверено).

Поля Kie.ai:

- `image_url` — одно изображение (JPEG/PNG/WEBP, до 10 МБ);
- `prompt` — необязательный, до 2000 символов; элементы можно пометить тегом `<bbox>x1 y1 x2 y2</bbox>`, координаты нормированы 0–1000, порядок **x перед y** (у FLUX 3 порядок другой — не путай);
- `max_images` 2–100, дефолт 30, включая базовый слой; оплата по фактически возвращенным;
- `text_recognition` — распознавание текстовых слоев, по умолчанию выключено;
- слои всегда PNG; `output_format` влияет только на базу; `size: auto` тарифицируется как 2K.

```text
Split this sale banner into separate layers: the headline <bbox>80 60 920 240</bbox>, the "Shop now" button <bbox>360 780 640 880</bbox>, the sneaker product <bbox>250 280 750 740</bbox>, and the clean background.
```

Перед запросом спроси, какие элементы нужны отдельно и для чего (передача дизайнеру, перевод текста, перекраска, анимация). Ставь `max_images` под реальное число элементов. После выдачи проверь: каждый слой имеет альфу, склейка совпадает с исходником, текст в текстовых слоях вычитан.

## 8. Текст

- Мелкий плотный текст улучшен, но брак остается: вычитывай каждую строку на финальном размере.
- Длинную копию разбивай на пронумерованные блоки с местом и иерархией (`seedream-5.md`, раздел 7). Факты, цифры, подписи — только утвержденные: `Do not invent any facts, statistics, dates, or extra labels`.
- **Кириллица:** официально не заявлена. Предупреди пользователя до генерации, держи русский текст коротким, вычитывай. Для критичного текста предложи набор шрифтом поверх изображения.
- Текст на прозрачном фоне: `transparent outside the lettering`, затем проверка альфы (раздел 6).

## 9. Референсы и серии

- Роли референсов — по `seedream-5.md`, раздел 5: у каждого вложения одна непересекающаяся роль; явно указывай, переносится только стиль или и содержание.
- Число референсов: официального лимита нет; у Picsart и Kie.ai — до 10. Проверяй у своего хоста.
- Серия персонажа: один и тот же набор референсов в каждом кадре плюс дословный identity block. Официально заявлено сохранение примет при таком подходе — проверяй лицо и одежду между кадрами.
- Перенос фактуры на текст (заявлено официально): `Apply the brushwork, colours, and material of Image 2 to the lettering "…"`.
- Синтаксис ссылок: теги `@Тег`, если среда их поддерживает; иначе `Image 1 / Image 2` по порядку загрузки. Не смешивай схемы.

## 10. Диагностика

| Симптом | Причина | Правка |
| --- | --- | --- |
| Правка задела соседние области | Широкая формулировка, нет preserve | `Change only …` + адресный preserve; проверь рамку diff |
| Цвет или детали уплывают за раунды | Наслаивание исправлений, JPEG-перекодирование | Откат к последнему чистому раунду, цепочка в PNG, одна правка за раунд |
| Модель перерисовала весь кадр | Промпт раунда переописал сцену целиком | Оставь только изменение и preserve-список |
| Вместо прозрачности белый фон или шахматка | Контрол прозрачности выключен, JPEG, слово `checkerboard` | Включи Transparent + PNG, убери слова про сетку, проверь альфу |
| Ореол или бахрома по краю | Края смешаны с невидимым фоном | Попроси чистый край (`clean anti-aliased edges, no halo`), проверь на темном и светлом фоне |
| Стекло или дым стали непрозрачными | Полупрозрачность не названа | Назови полупрозрачные части и что сквозь них видно |
| Мелкий текст с ошибками | Перегружен блок, кириллица | Сократи, разбей на блоки, вычитка; критичный текст — шрифтом поверх |
| Пластиковая кожа или пересвет | Теги `glossy`, `HDR`, `flawless` | Убери теги, опиши свет и текстуру кожи обычными словами |
| Хост вернул другой размер | Пересэмплирование в среде | Зафиксируй `size` и соотношение; сверяй раунды визуально |

## 11. Preflight

- Среда известна; контролы (прозрачность, размер, соотношение, число референсов) проверены в ее UI/API.
- Нет обещаний 4K, seed, маски, официального model ID и цены, если их нет у хоста.
- Для цепочки: база `R00` сохранена, одна правка за раунд, preserve-список есть, журнал `EDIT_LOG.md` ведется.
- Для прозрачности: контрол Transparent / `background: transparent`, PNG, нет слов про шахматку; полупрозрачные части названы.
- Текст дословно в кавычках; кириллица — с предупреждением.
- Формат локаций 21:9, если генерируется пространство.

## 12. Формат выдачи

Как в `seedream-5.md`, раздел 10: `Prompt` → `Suggested setup` → `Preserve`. Для цепочки правок добавь строку `Round: N (input: R0N-1)`. Для прозрачного ассета в `Suggested setup` укажи `Background: transparent, output: PNG` или фразу прозрачности в промпте, если контрола нет.
