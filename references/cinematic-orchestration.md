# Кинематографическая оркестрация

Этот файл связывает актуальный workflow `zauran-ai-creative` с четырьмя специализированными методами: CINEDANCE V4, Tig's Scene Engine, Tig's Acting Task и TIG BLOCKING MAP v2.

1. Приоритеты и зоны ответственности
2. Какие reference-файлы читать
3. Порядок работы
4. Единый контракт видеопромпта
5. Сцена и актёрская игра
6. Блокинг-карта
7. Режиссура кадра CINEDANCE
8. Разрешение конфликтов

10. Финальная QA

## 1. Приоритеты и зоны ответственности

При конфликте применяй такой порядок:

1. Последнее прямое указание пользователя.
2. Подтверждённый `BRIEF LOCK` и назначенные роли референсов.
3. Актуальный платформенный контракт выбранной модели: `seedance-2.5.md` для Seedance 2.5, `minimax-h3.md` для MiniMax H3, `gemini-omni-flash.md` для Gemini Omni Flash или пакет `seedance-2.0/` (через `seedance-2.0.md`) для Seedance 2.0 — режимы, параметры, reference map, first/last frames, keyframes, editing, extension, timestamps, формат полей и лимиты.
4. Ролевая методика текущего слоя: Scene Engine, Acting Task, Blocking Map или CINEDANCE.
5. Вендоренный пакет `seedance-2.0/` через маршрут `seedance-2.0.md` — моделе-независимые методы; для линии Seedance 2.0 он же платформенный источник.
6. Общие эвристики `video-and-continuity.md`, `storyboard-to-video.md` и другие правила навыка.
7. Рабочее предположение агента.

Не переносить устаревшие параметры Seedance 2.0 из CINEDANCE в Seedance 2.5. Та же граница для пакета `seedance-2.0/`: его длительности, лимиты, разрешения, model ID и наборы режимов относятся только к линии 2.0. Из CINEDANCE брать режиссёрскую логику кадра: изоляцию текущего шота, блокинг, FOV, камеру, физику, свет, звук и continuity.

Разделять уровни:

- `tig-scene-engine.md` отвечает за драматическую причинность.
- `tig-acting-task.md` отвечает за работу актёра и слушателя.
- `tig-blocking-map.md` отвечает только за геометрию и траектории.
- `cinedance-v4.md` собирает production-ready shot prompt.
- `seedance-2.5.md`, `minimax-h3.md` и `gemini-omni-flash.md` определяют актуальный способ отправки материалов, поддерживаемый режим и обязательный формат промпта для своей модели.

## 2. Какие reference-файлы читать

Всегда для сюжетного или кинематографического видео сначала полностью прочитать этот файл.

Затем загружать только нужные модули:

- Написание или аудит сцены/sequence/сценария: `tig-scene-engine.md`.
- Диалог, актёрская игра, реакция, слушание, живые глаза, плоская или переигранная игра: `tig-acting-task.md`.
- Точный multi-character staging, смена мест, позы, кроп, взгляд, trajectory/camera path map: `tig-blocking-map.md`.
- Любой production-ready prompt для Seedance/Higgsfield и ремонт нестабильной генерации: `cinedance-v4.md`.
- Выбор линзы, portrait/observation/wide/macro или lens drift: `cinedance-optics.md`.
- Два и более субъекта, диалог, first frame, left/right, gaze, landmark proximity, multi-shot: `cinedance-blocking.md`.
- Action, weather, liquid, weapon, vehicle, handheld, backlight, audio или reference hierarchy: `cinedance-physics-lighting.md`.
- Сюжетный, персонажный или перформанс-бриф до сборки промпта: `seedance-2.0/references/directors-read.md` через маршрут `seedance-2.0.md`.
- Несколько референсов с пересекающимися претензиями на identity, одежду, продукт, среду, свет, движение, камеру, тайминг, стиль или звук: `seedance-2.0/references/reference-transfer-contract.md`.
- Многоклиповая история, продолжение или ремонт хвоста: `seedance-2.0/references/sequence-project-state.md` и `seedance-2.0/references/continuation-handoff.md`.
- Вернувшийся тейк и решение «принять / чинить в посте / edit / перегенерировать / переписать»: `seedance-2.0/references/retake-protocol.md`.
- Ватный или слоповый финальный текст промпта: `seedance-2.0/references/anti-slop-lexicon.md` и `seedance-2.0/references/vocab/<язык>.md`.
- Блокировка фильтром, франшиза, бренд или реальный человек в промпте: `seedance-2.0/references/filter-vocab.md`, `seedance-2.0/skills/seedance-filter/GUIDE.md`, `seedance-2.0/skills/seedance-copyright/GUIDE.md`.

Для Seedance 2.5 дополнительно всегда читать `seedance-2.5.md`. Для MiniMax H3 / Hailuo H3 дополнительно всегда читать `minimax-h3.md`. Для Gemini Omni Flash дополнительно всегда читать `gemini-omni-flash.md` и по его маршруту — нужные companion-файлы `gemini-omni-flash-*.md`. Для image-to-video, start/end frame и continuity читать `video-and-continuity.md`. Для рекламной/product-раскадровки читать `storyboard-to-video.md`.

Не загружать Scene Engine и Acting Task для чистого product reveal без персонажей. Не загружать Blocking Map для простой single-subject сцены, если позиции уже надёжно фиксирует first frame.

## 3. Порядок работы

1. Зафиксировать `BRIEF LOCK`: результат, модель/режим, длительность, aspect, активные референсы, что сохраняется, что меняется, что запрещено.
2. Если бриф сюжетный, персонажный или перформанс — заполнить Director's Read (`seedance-2.0/references/directors-read.md`) как внутренний бриф и перевести его в видимые носители: блокинг, взгляд, жест, работа с предметом, конечная точка камеры, мотивированный свет, реплика, тишина, звуковой акцент. Для утилитарного, packshot, абстрактного или VFX-брифа драму не выдумывать: записать утилитарное намерение и явный отказ. Read никогда не идёт в текст промпта дословно.
3. Если сцена драматическая, проверить causal engine: Goal → Obstacle → Tactic → Reversal → Value Shift.
4. Если в кадре есть игра или диалог, построить ACTING TASK для каждого видимого персонажа, включая молчащих слушателей.
5. Если важна точная расстановка нескольких фигур, сначала создать staging reference по двухшаговому workflow Blocking Map и дождаться нужного этапа/подтверждения пользователя.
6. Составить current-shot packet: только активные subjects, refs, location, props, action, dialogue, timing, camera, lighting и audio.
7. Выбрать самый узкий актуальный mode целевой модели (Seedance 2.5, MiniMax H3, Gemini Omni Flash или Seedance 2.0) и назначить одну основную роль каждому материалу. Затем разрешить авторитет по измерениям: для каждого управляемого измерения (identity, одежда, продукт, среда, свет, движение, камера, тайминг, стиль, звук) назвать ровно одного владельца или пометить измерение неприменимым, убрать референс, не владеющий ничем, и явно записать, что из каждого референса не переносится.
8. Собрать один цельный английский prompt по объединённому контракту ниже.
9. Провести silent QA. Если пользователь просил только prompt, отдать prompt целиком. Если запросил генерацию, продолжить до файла и визуальной проверки. Вернувшийся тейк сортировать по `seedance-2.0/references/retake-protocol.md` и менять одну переменную за ретейк.

## 4. Единый контракт видеопромпта

Структуру промпта всегда диктует целевая модель, а CINEDANCE и остальные методики вставляются внутрь её блоков там, где усиливают контроль. Ниже сначала контракт Seedance 2.5, затем MiniMax H3, затем Gemini Omni Flash. Отдельного варианта для Seedance 2.0 здесь нет: его структуру, длину и синтаксис привязки референсов задаёт пакет — `seedance-2.0/references/prompt-compiler.md`, `seedance-2.0/references/surface-prompt-profiles.md` и `seedance-2.0/skills/seedance-prompt/GUIDE.md`; CINEDANCE, Scene Engine, Acting Task и Blocking Map вставляются в него так же, как в вариант 2.5, но числа берутся только из пакета.

### Вариант для Seedance 2.5

```text
GENERATION GOAL / SCENE CONTEXT
REFERENCE MAP
SUBJECT PROFILES / OBJECT LEDGER
LOCATION MAP
INITIAL STATE / FIRST FRAME AND SPATIAL BLOCKING
DRAMATIC AND ACTING DIRECTION (only when needed)
FORMAT MODE
OPTICS
CAMERA
TIMELINE / ACTION STAGES
PHYSICS AND MATERIAL BEHAVIOR
LIGHTING AND EXPOSURE
AUDIO
END STATE
MAINTAIN CONSISTENCY / LOCAL FAILURE-PREVENTION LOCKS
```

Правила сборки:

- Не дублировать параметры, уже надёжно выставленные в UI, если они не влияют на видимый/слышимый результат.
- Для каждого reference указать одну главную роль и exclusions. Не давать location-reference право управлять лицом или композицией, если он назначен только на среду.
- В prompt использовать только активные @tags текущего шота. Удалять номера сцен, stale-теги и prompt fragments ДРУГИХ шотов, `same as before` и невидимых персонажей. Это правило про мусор чужих шотов: активные требования и негативы текущего промпта из реестра требований не трогать.
- Negative list держать коротким. Сначала написать требуемое позитивное состояние, затем локальный запрет рядом с известным риском. Негативы, добавленные пользователем или подтверждённые прошлыми итерациями, не сокращать без его явной отмены.
- Для Seedance/Higgsfield по умолчанию писать финальный prompt на ясном кинематографическом английском. На другом языке — только по просьбе пользователя.
- После любой правки возвращать полный самодостаточный prompt, а не добавочный фрагмент; неизменённые блоки переносить дословно и сверять итог с реестром требований.

### Вариант для MiniMax H3

H3 не принимает секционный контракт Seedance. Здесь режиссёрские блоки не выносятся отдельными заголовками, а вплавляются в три официальных поля (для Ref2VA — в шесть секций). Полные правила формата и лимиты брать в `minimax-h3.md`.

```text
[строка выравнивания кадров — только для I2VA / FL2VA / L2VA]

integrated_multimodal_description: [Shot 1] стиль и композиция → subjects и их видимые признаки → локация и props → first-frame blocking → действие и actor beat → одно движение камеры → диалог с (S1) и <d>[Language] ...</d> → диегетический звук в момент события. [Shot 2] At 00:SS.mmm, ... только при осмысленной новой информации.

overall_soundscape: ambience, foley, невербальные звуки по всему клипу.

non_diegetic_music: инструменты, темп, ритм, динамика, либо N/A.
```

Куда уходят режиссёрские слои:

| Слой | Где живёт в H3 |
|---|---|
| Scene Engine: Goal → Obstacle → Tactic → Reversal → Value Shift | порядок действий и реакций внутри `integrated_multimodal_description`; на 4–15 секунд обычно один beat, а не вся арка |
| Acting Task | видимое действие к партнёру, взгляд и слушание внутри описания шота; без мимической хореографии |
| Blocking Map | first-frame occupancy, left/right, gaze и траектории в первых предложениях `[Shot 1]` и в описании перестроений |
| CINEDANCE optics и камера | естественный язык камеры H3 с одним именованным движением и опциональной амплитудой/скоростью |
| CINEDANCE physics и lighting | конкретные материалы, контакт, масса, направление света и экспозиция в тексте шота |
| CINEDANCE audio hierarchy | разделяется на три адреса: внутрисценный звук в описании, ambience и foley в `overall_soundscape`, закадровый счёт в `non_diegetic_music` |
| Reference map и роли материалов | только для Ref2VA — в `subject_definitions`, `summary` и `retention_analysis` |
| Локальные failure-prevention locks | короткие позитивные формулировки рядом с риском; отдельного negative-блока в формате H3 нет |

Дополнительные правила сборки для H3:

- Проверять длительность до написания: 4–15 секунд, поэтому многошотовый план и длинный диалог часто надо резать или разбивать на клипы.
- Пользовательские `@Теги` вложений не заменяют формат H3: в Ref2VA роль материала объявляется метками `<Subject N>`, `<Picture N>`, `<Video N>`, `<Audio N>`, а теги пользователя можно упомянуть только в сопроводительном списке ролей вне промпта.
- Русские реплики оставлять дословно внутри `<d>[Russian] ...</d>`, остальное описание писать по-английски.

### Вариант для Gemini Omni Flash

Omni не принимает ни секционный контракт Seedance, ни трёхполевой формат H3. Здесь всё уходит в **один связный английский абзац** плюс несколько отдельных предложений про звук, тайминг и негативы. Полные правила формата и лимиты брать в `gemini-omni-flash.md`.

Официальная анатомия — пять элементов DeepMind, и Google прямо пишет, что Omni требует **меньше** предписаний, чем Veo: задавай эффект, детали модель разрешит сама.

```text
[объявления медиа — только когда ролей больше двух:
 [# Sources <FIRST_FRAME>@Image1] [# References <IMAGE_REF_0>@Image2] ]

[continuity lock] [shot framing and motion] of [subject] [action] in [location].
[микро-движение]. [lighting]. [style].
[тайминг: "After 3 seconds, ..." либо блоки [0-3s] / [3-6s] / [6-10s]]
Sound design: [ambience], [SFX]. [музыка или "No music"].
[<кто именно> says: "<точная реплика>" либо "No dialogue."]
[негативы: "No embellishments." "No text overlay on screen."]

[закрывающая инструкция по медиа: "Use the given image(s) as references for video
 generation. The images should not be used as literal initial frames."]
```

Куда уходят режиссёрские слои:

| Слой | Где живёт в Omni |
|---|---|
| Scene Engine: Goal → Obstacle → Tactic → Reversal → Value Shift | порядок действий внутри одного абзаца; на 3–10 секунд это один beat, полная арка не помещается |
| Acting Task | видимое действие к партнёру, взгляд и слушание в описании; реплика — по грамматике `<описание говорящего> says [+ подача]: "<точная реплика>"` |
| Blocking Map | first-frame occupancy и left/right в первых предложениях; при нескольких персонажах — привязка через `<IMAGE_REF_N>` с явным сопоставлением «кто во что одет / что держит» |
| CINEDANCE optics | использовать для **выбора** оптики, но в промпт выносить уровень 1 словаря Omni (`push in`, `dolly zoom`, `locked off`, `oner`); полный телефото-стек Seedance сюда не переносить |
| CINEDANCE camera | одно именованное движение; continuity lock обязателен, иначе Omni сам нарежет несколько шотов |
| CINEDANCE physics | называть механизм, а не настроение; просить **одно** физическое событие — цепочки столкновений проваливаются |
| CINEDANCE lighting | отдельный элемент анатомии: откуда свет и какой эффект |
| CINEDANCE audio hierarchy | всё в прозе: внутрисценный звук и реплики в теле абзаца, ambience и foley после метки `Sound design:`, музыка отдельным предложением. Отдельных полей нет |
| Reference map и роли материалов | официальные теги `<FIRST_FRAME>`, `<LAST_FRAME>`, `<IMAGE_REF_N>`, `<VIDEO_REF_N>` и объявления `[# Sources ...]` / `[# References ...]` |
| Локальные failure-prevention locks | прямые негативы `No X` рядом с риском и `Keep everything else the same.` на правках; поля `negativePrompt` нет |

Дополнительные правила сборки для Omni:

- Проверять длительность и формат до написания: 3–10 секунд строкой `"8s"`, только 16:9 или 9:16. Многошотовый план длиннее 10 секунд собирается расширениями по 10 секунд до 40 суммарно, а не одной генерацией.
- Continuity lock ставить всегда, если многошотовость не нужна: `In a single unbroken scene` / `In a single continuous shot` / `No scene cuts` / `oner`.
- Пользовательские `@Теги` вложений не заменяют формат Omni: роль материала объявляется официальными метками, а теги пользователя перечисляются в сопроводительном списке ролей вне промпта.
- Длина: практический коридор ~50 слов на генерацию и 5–15 слов на правку. Мета-инструкция `Be extremely detailed…` просит добавить деталей модель, это не разрешение писать 500 слов.
- Промпт писать по-английски; неанглийские реплики брать в кавычки и предупреждать о разбросе — оценён официально только английский.
- Не переносить в промпт Omni секционные заголовки Seedance, поля H3 и параметры Veo.

## 5. Сцена и актёрская игра

Перед написанием драматической сцены назвать все пять элементов Scene Engine. Если неизвестен story goal, без которого removal test невозможен, задать короткий вопрос.

В video prompt не переносить весь структурный аудит. Переносить только то, что управляет видимым шотом:

- активный сценический Goal/направление;
- конкретный Obstacle/pressure;
- выбранную Tactic;
- beat, где происходит Reversal;
- наблюдаемое действие и реакцию, через которые зритель считывает Value Shift.

ACTING TASK строить только после чтения всего диалога сцены. Для каждого героя фиксировать:

- общую невысказанную `SCENE DIRECTION`;
- личный `MOTIVE`;
- личный playable `GOAL`;
- `OBSTACLE`, который может сломать линию;
- `TACTIC`: что герой делает с партнёром;
- moment-to-moment привязку к словам диалога;
- задачу глаз как действие, а не мимическую хореографию.

Не писать «играет печально», «поднимает брови», «глаза бегают» как основную режиссуру. Давать глаголы воздействия: проверяет, убеждает, скрывает, удерживает, испытывает, ловит ответ, сравнивает. Одна safety-line против frozen/unfocused stare допустима.

## 6. Блокинг-карта

Использовать TIG BLOCKING MAP, если модель путает места, левую/правую сторону, посадку, позы, кроп, взгляд или траектории.

Step 1 выдаёт отдельно:

1. Diagram-generation prompt по source frame как composition-only guide.
2. Будущий тег `@staging_[PROJECT]_[scene]_[version]`.
3. Тег source location `@loc_[PROJECT]_[name]_[scene]_[version]`.
4. Однострочный color key.

Не переходить к Step 2 без запроса/готовой карты. В diagram: front view со стороны камеры, тонкие приглушённые цветные контуры, без заливок, текста и букв; кропнутые тела не достраиваются.

Step 2 создаёт connector, в котором буквы A/B/C существуют только в тексте и связываются с цветами карты и реальными character tags. Connector писать позитивно: не упоминать graphic vocabulary карты даже как отрицание.

Attachment order: location и character references первыми, staging reference последней. В активном шоте использовать только одну актуальную версию карты.

## 7. Режиссура кадра CINEDANCE

Перед сборкой prompt молча пройти 4-D:

1. `Deconstruct`: оставить только текущий shot/sequence.
2. `Diagnose`: найти вероятные сбои.
3. `Develop`: построить prompt от references и blocking к optics, action, physics, light и audio.
4. `Deliver`: скрыть QA и отдать чистый результат.

Для каждого важного героя определить screen/world position, расстояние до landmark, body facing, gaze, movement direction и depth layer. Если герой должен быть виден сразу, явно закрепить first-frame occupancy.

Выбирать SINGLE CONTINUOUS TAKE по умолчанию. CONTROLLED MULTI-SHOT использовать только когда это действительно требуется. Каждый внутренний cut должен иметь тип, длительность, первый кадр, camera, blocking и действие; continuity не сбрасывается.

Управлять линзой через наблюдаемый результат и физическую дистанцию камеры. Использовать FOV anchors из `cinedance-optics.md`; не полагаться только на миллиметры, f-stop, ISO или название линзы.

Описывать камеру как физическое поведение оператора. Для handheld использовать дыхание, массу, weight shift и micro-corrections; не заменять это random shake.

Закреплять гравитацию, массу, контакт, инерцию, friction, follow-through, cloth/hair delay и поведение материала. Свет задавать как priority lock с направлением, camera side, exposure target и запрещённым flat-light failure.

В аудио разрешать только заданную реплику и назначенные ambience/SFX/BGM. Явно закреплять speaker, язык, timing и lip sync; у молчащих персонажей губы неподвижны.

## 8. Разрешение конфликтов

- Пользователь просит morph: не сохранять общий `no morph`; ограничить morph только утверждённой областью и сохранить anchor.
- Seedance 2.5 и CINEDANCE расходятся по формату: следовать `seedance-2.5.md` по mode/reference/API, а CINEDANCE — по видимому shot control.
- MiniMax H3 и CINEDANCE расходятся по формату: следовать `minimax-h3.md` по режиму, полям, меткам и лимитам, а CINEDANCE — по содержанию кадра. Не выносить в H3 заголовки секций Seedance и не заводить отдельный negative-блок.
- Задуманный многошотовый ролик не помещается в 4–15 секунд H3: сократить до одного beat или разбить на отдельные клипы с явной continuity, а не ужимать диалог до нечитаемого lip sync.
- Gemini Omni Flash и CINEDANCE расходятся по формату: следовать `gemini-omni-flash.md` по режиму, лимитам, тегам медиа и грамматике промпта, а CINEDANCE — по содержанию кадра. Не выносить в Omni заголовки секций Seedance, не заводить отдельный negative-блок и не переносить параметры Veo. Оптику из `cinedance-optics.md` использовать для выбора, но формулировать словарём Omni.
- Задуманный ролик не помещается в 3–10 секунд Omni: собирать расширениями по 10 секунд до 40 суммарно (только в хвост), а не пытаться уместить всё в одну генерацию. Помнить, что при расширении `0s` отсчитывается от начала продлённой части.
- Пакет `seedance-2.0/` расходится с платформенным файлом модели: следовать платформенному файлу навыка, из пакета брать только ремесло. Не выносить в промпт другой модели ни одно число, model ID или название площадки из пакета и не заменять `@Тег` пользователя на `@Image1` / `@Video1` из пакета.
- Storyboard показывает стрелки/подписи: создать clean generation pack. Не надеяться, что negative prompt удалит пиксели.
- Staging map конфликтует со style/wardrobe: identity и location refs управляют внешностью; карта — только positions. Поставить её последней.
- Acting direction конфликтует с точной позой: поза задаёт стартовую геометрию, Acting Task — внутреннюю тактику и допустимое действие внутри этой геометрии.
- Scene Engine требует reversal, но это один escalation shot внутри незавершённой sequence: не вставлять искусственный поворот. Reversal обязателен на разрешённую sequence, не на каждый shot.

## 9. Диагностика результата

- Сцена информативна, но мёртвая: проверить реальный Obstacle, информационный выход Tactic и Value Shift.
- Лицо плоское/стеклянное: переписать Acting Task как действие к партнёру; не лечить светом или catchlight.
- Персонажи поменялись местами: обновить Blocking Map, first-frame lock, body/gaze directions и version tags.
- Lens drift: добавить FOV outcome stack и anti-drift lock, проверить соответствие content class.
- CG/невесомая пластика: усилить массу, контакт, acceleration/deceleration, ground pressure и follow-through.
- Плоский свет: закрепить camera side, source direction, exposure priority и допустимую тень.
- Случайные персонажи/props: удалить stale references и прошлый контекст; оставить only active list.
- Ошибка после cut: проверить continuity ledger — left/right, gaze, light, ownership, wounds, dirt/liquid/prop state и emotional progression.

## 10. Финальная QA

Перед prompt delivery проверить:

- выбран правильный mode целевой модели: Seedance 2.5, самый узкий режим MiniMax H3 или режим Gemini Omni Flash;
- у каждого материала есть role и exclusion;
- active refs не содержат stale tags;
- first frame занят нужными subjects;
- blocking, body direction, gaze и landmark proximity однозначны;
- Acting Task направлен на партнёра, а не на мимику;
- lens соответствует content class и защищена от drift;
- камера имеет ноль или одно осмысленное движение на shot;
- timeline физически помещается во время;
- object count, ownership и hand state непротиворечивы;
- physics, light и audio имеют причинный контроль;
- cuts названы и не сбрасывают continuity;
- end state проверяем и удерживается;
- prompt полный, цельный, английский и не содержит внутренний QA.

Дополнительно для MiniMax H3:

- строка выравнивания стоит первой и точной для I2VA/FL2VA/L2VA, длительность в формате `S.SS`;
- присутствуют все три поля, а для Ref2VA — все шесть секций в фиксированном порядке;
- `[Shot 1]` без таймкода, дальнейшие таймкоды строго возрастают и помещаются в 4–15 секунд;
- диалог дословный, с языковым тегом и устойчивым `(S1)`, у молчащих персонажей губы сомкнуты;
- внутрисценная музыка стоит в описании, а не в `non_diegetic_music`; `N/A` только для намеренного отсутствия.

Дополнительно для Gemini Omni Flash:

- длительность 3–10 секунд задана строкой (`"8s"`), соотношение только `16:9` или `9:16`, `1080p`/`4k` заявлены как апскейл 720p, а не нативный рендер;
- continuity lock стоит, если многошотовость не нужна — иначе модель нарежет шоты сама;
- звук описан явно: ambience после `Sound design:`, музыка отдельным предложением, `No dialogue` при отсутствии реплик;
- при правке видео со звуком решено, сохраняем исходную дорожку или вырезаем аудиопоток до загрузки; промптом это не достигается;
- каждое медиа привязано официальным тегом, нумерация `<IMAGE_REF_N>` (с 0, только по референсам) не спутана с `@ImageN` (с 1, по всем изображениям включая кадры-якоря);
- не передаются `temperature`, `negative_prompt`, `person_generation`, `seed`, `duration_seconds` и прочие параметры Veo;
- при загруженном видео проверено региональное ограничение (EEA, Швейцария, Великобритания, часть штатов США);
- после генерации проверено наличие реального видеоконтента, а не только код 200 — тихий отказ возвращает `completed` без видео, а ответ быстрее 10 секунд означает блокировку.

После генерации следовать `qa-and-delivery.md`: просмотреть ролик целиком и по contact sheet, проверить identity, positions, physics, camera, audio, final hold и фактические параметры файла.
