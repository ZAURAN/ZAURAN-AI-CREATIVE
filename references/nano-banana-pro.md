# Nano Banana Pro (Gemini 3 Pro Image) — платформенный контракт

Обязательный файл, когда генерация или редактирование изображения идет на Nano Banana Pro. Он владеет параметрами, лимитами, синтаксисом API, контрактом промпта и диагностикой для этой модели — как `gpt-image-2.md` для GPT Image и `seedream-5.md` для Seedream 5.0.

Не применяй файл к другим моделям и к видео. Числа, поля и model ID отсюда не переносятся ни на GPT Image, ни на Seedream, ни на Seedance/H3/Omni.

Три источника знаний по модели, в порядке приоритета:

1. **Этот файл** — официальные факты Google (Gemini API docs, DeepMind, blog.google, официальный prompting guide), сверено 2026-09-01.
2. **Заметка Obsidian** `02 · Nano Banana Pro (Gemini 3 Pro Image).md` — практика и подтвержденные пользователем настройки. При конфликте с этим файлом побеждает **последний подтвержденный тест пользователя**, а не общая документация.
3. **Библиотека рецептов** `nano-banana-pro/` — 70 промтов сообщества. Донор формы, не контракт: лимиты и параметры не задает (разделы 11–14).

Если база Obsidian недоступна, скажи об этом одной строкой и работай по этому файлу.

## 2. Параметры генерации

### Interactions API (актуальный)

```json
{
  "model": "gemini-3-pro-image",
  "input": "…",
  "response_format": {
    "type": "image",
    "aspect_ratio": "16:9",
    "image_size": "4K",
    "mime_type": "image/png",
    "delivery": "inline"
  }
}
```

- `image_size`: `"512"` (0.5K), `"1K"`, `"2K"`, `"4K"`. Pro поддерживает весь диапазон; `gemini-3.1-flash-lite-image` — только 1K.
- `mime_type`: `image/png` или `image/jpeg`. `delivery`: `inline` или `uri`.
- Прочее в generation config: `max_output_tokens`, `seed`, `stream`, `background`.
- Изображения на входе передаются как `ImageContent`: `type: "image"` + `mime_type` + `data` (base64) или `uri`.

### Generate Content API (legacy)

Страница помечена Google как legacy. Поля другие:

```json
{
  "generationConfig": {
    "responseModalities": ["TEXT", "IMAGE"],
    "imageConfig": { "aspectRatio": "16:9", "imageSize": "2K" }
  }
}
```

В части документации и SDK та же настройка встречается как `responseFormat.image.{aspectRatio,imageSize}`. **Написание поля зависит от версии SDK** — сверяй по своему клиенту, а не по памяти.

### Соотношения сторон

Документированный набор для линии Gemini 3 Image: `1:1`, `2:3`, `3:2`, `3:4`, `4:3`, `4:5`, `5:4`, `9:16`, `16:9`, `21:9`, плюс экстремальные `1:4`, `4:1`, `1:8`, `8:1`.

Многие хосты и врапперы принимают только подмножество (часто `1:1`, `16:9`, `9:16`, `4:3`, `3:4`). Перед обещанием экзотического кадра проверь список в конкретном интерфейсе.

### Что модели не существует

Нет отдельного `negative_prompt`. Нет `person_generation`. Нет отключения thinking. Запреты пишутся словами внутри промпта (раздел 5).

## 3. Что модель умеет

- **Текст в кадре** — сильнейшая сторона: длинные пассажи, мультиязычная верстка, читаемые надписи для постеров, меню, диаграмм и инфографики.
- **Thinking включен по умолчанию и не отключается.** Модель рассуждает перед рендером и делает промежуточные «thought images» — они не тарифицируются.
- **Grounding через Google Search** (`google_search` tool): факты и актуальные данные подтягиваются в изображение. Для инфографики по реальным данным — включать.
- **Interleaved output**: может выдать связку «текст + иллюстрации» (истории, инструкции) за один проход.
- **Студийное редактирование**: локальные правки, смена света (день→ночь, боке), угол камеры, фокус и глубина резкости, цветокоррекция, смена соотношения сторон.
- **Консистентность личности** до 5 человек в кадре.
- **Смешивание референсов** — до 14 изображений.
- **SynthID** во всех выдачах. В приложении Gemini на free и Pro тарифах добавляется видимая метка «Gemini sparkle»; она снимается у AI Ultra и в AI Studio.

## 4. Референсы

| Параметр | Значение |
| --- | --- |
| Максимум изображений на входе | **14** («for best results … include a maximum of 14 images in an input», Google Cloud docs) |
| Высокая точность объектов | до **6** объектов |
| Консистентность людей | до **5** человек |
| Style-референсы | до 3 — цифра встречается в таблице документации, но принадлежность именно Pro не подтверждена; считай гипотезой |
| Аудио и видео на входе | не поддерживаются |

Источники расходятся: таблица Gemini API для Pro называет только «до 6 изображений объектов с высокой точностью», маркетинг и Cloud-документация говорят о 14 на входе, сторонний разбор считает реальный потолок 6+5=11. **Рабочее правило: планируй до 6 «важных» референсов, чьи детали должны дойти до кадра; всё сверх этого считай контекстом, а не гарантией.** Точное число под конкретный интерфейс проси проверить у пользователя.

**Как ссылаться на вложения** — порядок навыка:

1. Пользователь дал теги вложениям → строго `@Тег` (правило навыка, раздел 5 `SKILL.md`).
2. Тегов нет, вложений несколько → `Image 1` / `Image 2`, как в официальных примерах Google («Keep the person's facial features exactly the same as Image 1»).
3. Одно вложение → обычная фраза: `the person in this image`, `the attached photo`.

Официальных меток вида `<IMAGE_REF_N>` у этой модели **нет** — они принадлежат Gemini Omni Flash. Не переноси.

Роль каждому референсу назначай по общему правилу навыка и разрешай авторитет по измерениям: identity, одежда, продукт, среда, свет, камера, стиль — ровно один владелец на измерение.

## 5. Контракт промпта

### Пять обязательных элементов (официально)

1. **Subject** — кто или что, конкретно.
2. **Composition** — как построен кадр: крупность, ракурс, план.
3. **Action** — что происходит.
4. **Location** — где.
5. **Style** — общая эстетика.

### Продвинутые управляющие слои (официально)

- **Формат**: соотношение сторон и разрешение прямо словами («a 9:16 vertical poster», «a cinematic 21:9 wide shot»).
- **Камера и свет**: «a low-angle shot with a shallow depth of field (f/1.8)», «golden hour backlighting creating long shadows».
- **Текст**: дословно что написать и как оно должно выглядеть.
- **Фактические ограничения**: если данные должны быть точными — сказать это явно и дать верные входные данные.
- **Запреты**: отдельного negative-поля нет — пиши их словами внутри промпта, рядом с тем, к чему они относятся (`Do not distort the original center image`, `no text on the packaging`). Пользовательские негативы из реестра требований переносятся дословно.

### Порядок блоков для сложного запроса (официальный guide Google)

```
1. Главная инструкция — что создаем и зачем
2. Face Consistency — если есть референс личности
3. Action / Expression — поза, эмоция, изменение
4. Placement — где субъект в кадре
5. Graphics / Elements — стрелки, фигуры, визуальная иерархия
6. Text — дословная строка в кавычках + стиль (цвет, обводка, тень)
7. Background — окружение, свет, насыщенность
8. Format — соотношение сторон, разрешение
```

Для простого кадра этот порядок избыточен — бери общий порядок навыка из `photo-and-storyboard.md`.

### Четыре золотых правила Google

1. **Править, а не перегенерировать.** Разговорная правка дешевле и точнее нового прогона.
2. **Живой язык вместо тегов.** Плохо: `Cool car, neon, city, night, 8k`. Хорошо: связное предложение с намерением.
3. **Конкретика и фактура**: `matte finish`, `brushed steel`, `soft velvet`.
4. **Контекст и назначение.** «для премиального бразильского кулинарного альбома» задает модели подачу и свет лучше, чем десять прилагательных.

Язык промпта — английский по умолчанию навыка. Модель понимает и другие, но мультиязычный текст **внутри кадра** — отдельная задача (раздел 6).

## 6. Текст на изображении

- Дословную строку давай **в кавычках** и указывай место: «Overlay massive, pop-style text in the middle: "…"».
- Задавай стиль отдельно: цвет, обводка, тень, шрифтовой характер («technical architectural font», «hand-drawn whiteboard markers»).
- Требуй читаемость явно, если надпись мелкая или стилизованная.
- Официальная рекомендация Google для сложных случаев: **сначала получить сам текст, потом генерировать изображение с этим текстом** — не заставлять модель одновременно сочинять и верстать.
- Мелкий текст, тонкие детали и точная орфография — заявленная слабость. Для критичной надписи планируй проверку и, при необходимости, доверстку в редакторе.
- Мультиязычный текст может содержать грамматические ошибки и промахи по культурному контексту. Для рекламной локализации — обязательная вычитка носителем.

## 7. Редактирование

- Формула правки: **что меняется + что остается неизменным**. Второе так же обязательно, как первое.
- Рабочие формулировки: `Keep the [element] exactly the same`, `Keep facial features exactly the same as Image 1`, `Keep everything else in the image the same, preserving the original style, lighting and composition`.
- Локальная правка задается **семантически**, а не маской: «fill this glass with liquid», «remove the people behind the subject and fill the space with matching background».
- Поддержано: смена света (день↔ночь, боке), угол камеры, фокус и ГРИП, цветокоррекция, расширение кадра под другое соотношение сторон, удаление объектов.
- Слабость: смешивание и сложная смена света иногда дают неестественные артефакты. Проверяй стыки, тени и контактные точки.
- Правило навыка сохраняется: `LOCKED` и `EDITABLE` фиксируются до запуска, preserve-список пишется явно.

## 8. Разрешение, цены и реальный 4K

| Разрешение | Токенов на выходе | Цена за изображение (standard) | Batch |
| --- | --- | --- | --- |
| 1K (≈1 Мп) | 1120 | $0.134 | $0.067 |
| 2K (≈4 Мп) | 1120 | $0.134 | $0.067 |
| 4K (≈16 Мп) | 2000 | $0.24 | $0.12 |

Вход: $2.00 / 1M токенов текста и изображений (≈$0.0011 за входное изображение). Выход: $12 / 1M за текст и thinking, $120 / 1M за изображения. Batch — вдвое дешевле.

**Известный дефект.** `image_size` / `imageSize` в ряде SDK и прокси игнорируется: запрос 2K или 4K возвращает 1024×1024 или 1408×768. Подтверждено на `@google/genai` (Node) на нескольких версиях; лечится обновлением SDK либо переносом кода из Playground, официального объяснения нет. Практический вывод для навыка: **после генерации проверяй фактический размер файла, а не заявленный параметр.** Слова `4K` и `ultra-detailed` в теле промпта влияют на проработку, но разрешения не задают — это общее правило навыка о 4K.

## 9. Preflight перед генерацией

1. Модель точно Pro, а не `gemini-2.5-flash-image` и не `gemini-3.1-flash-image`?
2. Среда: прямой API (Interactions или legacy), AI Studio, приложение Gemini, Vertex, Flow или сторонний враппер? От нее зависят доступные `aspect_ratio`, `image_size` и число референсов.
3. Соотношение сторон есть в списке этого интерфейса?
4. Референсов не больше 14, «важных» не больше 6, людей не больше 5? У каждого одна роль и один владелец на измерение?
5. Ссылки на вложения оформлены по правилу раздела 4 (`@Тег` → `Image N` → фраза)?
6. Текст в кадре — дословно, в кавычках, с местом и стилем?
7. Запреты записаны словами внутри промпта, а не в несуществующее negative-поле?
8. Если данные фактические — включен grounding и данные проверены?
9. Нужен ли реальный 4K и выставлен ли он параметром, а не словом?

## 10. Диагностика

| Симптом | Причина | Правка |
| --- | --- | --- |
| Пришло 1024×1024 вместо 2K/4K | SDK или прокси игнорирует `image_size` | Обновить SDK, взять код из Playground, проверить фактический размер файла; при невозможности — апскейл |
| Лицо «уплыло» при правке | нет явного лока личности | Добавить `Keep facial features exactly the same as Image 1` перед описанием изменений |
| Изменилось то, что менять не просили | не задана граница правки | Добавить `Keep everything else the same` плюс явный preserve-список |
| Мелкая надпись нечитаема, орфография битая | заявленная слабость модели | Увеличить кегль и место под текст, упростить строку, сгенерировать текст отдельно и затем кадр, при критичности — доверстка |
| Инфографика красивая, но цифры выдуманы | нет grounding и нет заданных данных | Включить `google_search` либо передать точные данные в промпте и потребовать их дословного использования |
| Пришел только текст, изображения нет | промпт неоднозначен для модели | Переписать как прямую инструкцию «создай изображение …» с конкретным субъектом |
| Отказ и сообщение о небезопасном запросе | сработал контентный фильтр | Переписать без запрещенных сущностей, сохранив замысел; людей по реальному лицу и публичных лиц — по правилам навыка и площадки |
| Артефакты на стыках после смены света | слабость blending и lighting-правок | Разбить на две правки, менять один слой за итерацию, проверить тени и контакты |
| Модель выдала не то число изображений | документированное поведение | Просить по одному изображению за запрос |
| Экзотическое соотношение не применилось | хост принимает подмножество | Проверить список в интерфейсе, выбрать ближайшее поддерживаемое, при необходимости кадрировать после |

## 12. Приёмы, подтверждённые корпусом

Что реально повторяется в 70 рецептах, с числом вхождений. Совпадает с официальным гайдом там, где они пересекаются, — считай это независимым подтверждением.

1. **Свет — самый частый управляющий слой** (44/70): `harsh super-flash`, `rim light`, `golden hour`, `softbox`. Нет строки про свет — промт недоделан.
2. **Негативы формулируются внутри тела промта** (26/70): `Do not distort the original center image`, `avoid`, `without`. Отдельного negative-поля у модели нет — запрет пишется рядом с тем, к чему относится.
3. **Текст на изображении заказывается явно** (25/70): дословная строка, место в кадре, роль. В кавычках — правило навыка.
4. **Камера и оптика проговариваются словами** (20/70): `fisheye`, `wide-angle`, `85mm`, `bokeh`, `depth of field`, тип съёмки.
5. **Ссылка на загруженное изображение** (19/70): обычной фразой при одном вложении; `Image 1` / `Image 2` при нескольких (рецепты 4.1 и 8.1). Порядок навыка — раздел 4.
6. **Явный лок личности** (6/70): `"face": {"preserve_original": true}`, `keep the facial identity unchanged`. Для портрета по фото пользователя — обязательная строка.
7. **Соотношение сторон в теле промпта** (10/70): `expand this image to a 16:9 aspect ratio`. Не полагаться только на поле интерфейса, когда кадр перестраивается.
8. **JSON-тело для сложной сцены** (9/70): блоки `subject / accessories / photography / background`. Брать, когда управляемых сущностей больше пяти; для простого кадра лишнее.
9. **Именованные шаги-инструкции** (30/70; строго нумерованных `1. 2. 3.` только 4/70): `Face Consistency : …`, `Context Awareness : …`, `Crucial Fit Details : …`. Метка плюс требование через двоеточие работает как чек-лист. Это ровно то, что рекомендует официальный guide.
10. **Разрешение и детализация словами** (11/70): `2K`, `ultra-detailed`, `crisp details`. Влияет на проработку, но **не заменяет реальный параметр размера**.

## 13. Правила использования донора

- **Донор даёт форму, бриф даёт содержание.** Структура, лексика стиля, свет, композиция — из рецепта. Герой, продукт, локация, текст, ограничения — из `BRIEF LOCK`. Не подставлять пользователю чужую сцену целиком.
- **Атрибуция.** У каждого рецепта в поле `source` есть ссылка на автора (X, WeChat, Replicate). При заметном заимствовании ставь строку `Промт-донор: awesome-nanobanana-pro (id N.M, автор <label>)`.
- **Плейсхолдеры закрывать.** В рецептах встречаются «yourself», «my photo», описания чужой внешности — заменять на реальные субъекты брифа.
- **Не переносить на другие модели.** Для GPT Image действует `gpt-image-2.md`, для Seedream 5.0 — `seedream-5.md`.
- **Реклама в файле.** В начале `AWESOME-NBP.md` спонсорские блоки (APIMart, Cyberbara, Doloffer), в конце — Star History. Это реклама репозитория, не знание. Никогда не предлагать эти сервисы пользователю. Баннеры (`./assets/*`) не копировались — две-три картинки в файле не откроются, это ожидаемо.
- **Картинки-сэмплы.** Ссылки внешние (`github.com/user-attachments/…`, `pbs.twimg.com`). Годятся как превью, но не проверены и могут пропасть.

## 14. Когда брать этот донор, а когда YouMind

- Цель — Nano Banana Pro → сначала этот файл, `youmind-prompt-library.md` вторым.
- Задача попадает в один из 10 разделов и нужен проверенный приём → этот донор: маленький, курируемый, с живой атрибуцией и готовыми JSON-каркасами.
- Нужна широта, редкая ниша или подбор по стилю с сэмплами → `youmind-prompt-library.md` (15 373 промта; тоже собран с `youmind.com/nano-banana-pro-prompts`, так что для этой модели релевантны оба — маленький курируемый первым, большой для перебора).

## 15. Что не подтверждено

Помечай как гипотезу и проси пользователя сверить в своем интерфейсе:

- Точное число style-референсов для Pro (цифра 3 в таблице документации может относиться к другой модели линии).
- Реальный потолок входных изображений в конкретном хосте: официально «до 14 на входе», но гарантия высокой точности документирована только на 6 объектов.
- Написание поля размера в текущей версии SDK: `imageConfig.imageSize` против `responseFormat.image.imageSize`.
- Полный список соотношений сторон конкретного интерфейса.
- Ограничения на генерацию людей: в приложении Gemini они привязаны к тарифу, для API отдельного параметра нет — политика площадки проверяется на месте.
- Статус `gemini-3-pro-image` против `gemini-3-pro-image-preview` у конкретного провайдера.
