# Gemini Omni Flash — рабочая инструкция

Используй этот документ для Google **Gemini Omni 1.1 Flash** (`gemini-omni-1.1-flash`): text-to-video, image-to-video, интерполяция first/last frame, генерация по референсам, редактирование видео, расширение сцены до 40 секунд, встроенное аудио, диалог и текст в кадре.

Источники: официальная документация Gemini API (`ai.google.dev/gemini-api/docs/omni`, model card, REST-референс `ai.google.dev/api/interactions-api`), prompt guide Google DeepMind, официальный агентский скилл Google `google-gemini/gemini-skills/skills/gemini-omni-flash-api` вместе с его исполняемым кодом, документация Gemini Enterprise Agent Platform, справка Google Flow и инструментированные тесты практиков. Состояние на 28 августа 2026. GA модели — 27 августа 2026.

То, что Google не публикует, перечислено как открытые пробелы в `gemini-omni-flash-failures.md` — **значения для них не выдумывай**. Если пользователю нужна цифра, которой там нет, скажи, что она не опубликована, и предложи проверяемый способ её выяснить.

## 0. Два факта до начала работы

**Модель существует.** `gemini-omni-1.1-flash` вышел в GA 27 августа 2026 — позже большинства обучающих срезов. Не пиши пользователю «не могу подтвердить, что такая модель есть», не хеджируй ID и не подменяй его на Veo «потому что это видеомодель Google». Этот файл — источник истины.

**Не пиши код Veo.** Скатывание в Veo API — самая частая ошибка на этой модели. Для Omni **не существует**:

`client.models.generate_videos()` · `predictLongRunning` / `fetchPredictOperation` · `GenerateVideosConfig` · `duration_seconds` / `durationSeconds` · `negative_prompt` / `negativePrompt` · `person_generation` / `personGeneration` · `generate_audio` · `number_of_videos` / `sampleCount` · `reference_images=` / `VideoGenerationReferenceImage` · `storageUri` · `fps` · `system_instruction` · `temperature` · `top_p` · stop sequences · опрос через `client.operations.get()` · поля ответа `raiMediaFilteredCount` / `raiMediaFilteredReasons` · блок `NEGATIVE:` внутри промпта.

Omni работает через `client.interactions.create()`, `response_format`, `generation_config.video_config.task`, `previous_interaction_id`, негативы формулировкой `No X` прямо в промпте и теги `<FIRST_FRAME>` / `<IMAGE_REF_N>` / `<VIDEO_REF_N>`.

Отдельно: предупреждение о скрытом переписывании промпта (prompt rewriter) относится **только к Veo**. У Omni нет поля вида `enhance_prompt`, и страница Google про отключение rewriter озаглавлена для Veo. Не пугай пользователя этим.

## 1. Что это за модель и когда её брать

Вход: текст, изображение, видео (до 10 секунд для редактирования и расширения). Выход: **всегда видео со звуком**, никогда текстовый ответ. Это не текстовая Gemini 2.5/3.x Flash и не Nano Banana.

Официальная позиция Google: *«Используй Gemini Omni Flash как модель по умолчанию для генерации видео»* — за когерентность видео, multi-input reasoning, консистентность персонажа, фактическую точность и многоходовое разговорное редактирование. Veo берут ради специфических возможностей и совместимости со старыми пайплайнами.

Инструментированное сравнение 8 задач: Omni выиграл 5/8 (4.124/5) против Veo 3.1 Fast 3/8 (4.009/5), примерно **втрое быстрее** (29.3 с против 97.4 с) и дешевле за файл. Omni сильнее в **следовании инструкции**; Veo — в **визуальном лоске и качестве звука**. Практический вывод: Omni — рабочая лошадка на основной объём таймлайна, hero-шот с нативным 1080p+ и вещательным звуком имеет смысл отдать другой модели.

Слабо подтверждённые вторичные сравнения: Omni уступает Kling 3.0 по консистентности человеческого движения и Sora 2 по достоверности среды.

## 2. Сначала выбери режим

- **Text-to-video:** сцена задаётся только текстом.
- **Image-to-video:** одно изображение как отправная точка движения.
- **First / first-and-last frame (интерполяция):** два изображения задают старт и финал; одинаковое изображение в обеих ролях даёт **зацикленное** видео.
- **Reference-to-video:** изображения и/или видео задают личность, объект или стиль, но **не пиксели кадра**.
- **Video editing:** исходное видео — master; меняется только названная область.
- **Video extension:** продолжение в хвост клипа, шагами по 10 секунд, до 40 секунд суммарно.

Режим можно не объявлять параметром — модель выводит его из промпта, и Google это **рекомендует**. Поле `task` включай только когда промпт не сработал, потому что оно накладывает два конкретных ограничения: **отключает мультимодальные референсы** (при `task="extend"` нельзя передать ни референсные изображения, ни видео) и **несовместимо с `previous_interaction_id`**, то есть ломает цепочку правок. Подробности — `gemini-omni-flash-api.md`.

## 3. Правило `@Тег` для этой модели

Общее правило навыка — ссылаться на вложения пользователя как `@Тег` — здесь **действует с исключением, аналогичным MiniMax H3**.

Omni имеет собственные официальные метки ролей: `<FIRST_FRAME>`, `<LAST_FRAME>`, `<IMAGE_REF_N>`, `<VIDEO_REF_N>` и объявления `[# Sources ...]` / `[# References ...]`. Внутри промпта роль материала объявляется **только ими** — модель не понимает `@Тег`.

Порядок работы:

1. В сопроводительном списке ролей **вне промпта** сопоставь теги пользователя официальным меткам: `@Шот с норм лицом → <IMAGE_REF_0>`, `@Очки → <IMAGE_REF_1>`.
2. Внутри промпта используй только официальные метки.
3. Порядок частей в `input` должен точно соответствовать нумерации меток — см. `gemini-omni-flash-media.md`, там же правило нумерации `@ImageN`, которого нет в прозе Google.

## 4. Три правила, на которых ломается большинство промптов

**1. Omni по умолчанию режет на несколько шотов.** Он сам придумает монтажную последовательность и нарратив. Нужен один кадр — скажи дословно: `In a single unbroken scene` / `In a single continuous shot` / `No scene cuts` / `one continuous shot` / `oner`.

**2. Звук генерируется всегда, в том же проходе, и управляется только текстом промпта.** Нет флага аудио, нет mute, нет отдельного поля. Не описал звук — получишь то, что решит модель. Редактируешь видео **со звуком** — Omni сохранит и адаптирует этот звук; единственный способ получить новую дорожку — физически удалить аудиопоток из файла до загрузки. Подробно: `gemini-omni-flash-audio.md`.

**3. Редактирование хочет коротких промптов, генерация — насыщенных.** Дословно у Google: *«Simple prompts work best for video editing. Overly descriptive prompts can lead to unintended changes.»* Каждая правка заканчивается `Keep everything else the same.`

## 5. Анатомия промпта — официальные пять элементов

DeepMind называет ровно пять и прямо пишет, что Omni требует **меньше** предписаний, чем Veo: скажи, что хочешь создать, а не как отрисовать каждый кадр.

| Элемент | Что задавать |
|---|---|
| **Shot framing and motion** | крупность (wide / medium / close-up); как движется камера — плавно скользит или резко бросается |
| **Style** | ощущение сцены: реалистично или кинематографично, приземлённо или величественно — задавай **эффект**, детали модель добирает сама |
| **Lighting** | откуда свет (солнце, фонарь, источник за кадром) и какой эффект даёт: резкий, тёплый, эфирный |
| **Location** | место на уровне намерения («инопланетный ландшафт с прозрачной лазурной водой»), без описи каждой мелочи |
| **Action** | что происходит, кто и какие объекты в кадре, как они движутся и взаимодействуют |

Затем отдельными предложениями: **звук**, **тайминг**, **негативы**.

Рабочая форма для новой генерации:

```text
[continuity lock] [крупность и движение камеры] of [субъект] [действие] in [локация].
[микро-движение — деталь]. [свет]. [стиль].
Sound design: [ambience], [SFX]. [музыка или "No music"].
[No dialogue. / <кто именно> says: "<точная реплика>"]
```

Официальный пример Google — одним связным абзацем, не списком тегов:

```text
Continuous, unbroken handheld shot of a fluffy tabby cat sitting on a sunny windowsill, looking out into a leafy garden. The cat's tail twitches slowly, and its ears rotate slightly toward ambient noises. Sunbeams illuminate dust motes in the air. Sound design: Gentle breeze, distant bird chirps. No dialogue.
```

**Свалка ключевых слов работает хуже.** `woman, violin, field, golden light` слабее предложения. То же с нагромождением прилагательных в стиле Veo и с ярлыками настроения — «make it cinematic» это канонический плохой промпт.

Длина: технический потолок огромен (контекст 1 048 576 токенов), практики советуют держаться **до ~50 слов** на генерацию. Собственные примеры Google — 30–80 слов на генерацию и 5–15 на правку. Мета-инструкция `Be extremely detailed…` (см. §8) просит добавить деталей **модель**, это не разрешение писать 500 слов.

## 6. Негативы — обычное «No X»

У Omni **нет параметра `negativePrompt`**. Собственная документация Omni, cookbook, исполняемый скилл Google и DeepMind используют прямое отрицание прямо в промпте:

```text
No dialogue
No embellishments
No extra sound effects
No dialogue or voiceover.
No text overlay on screen.
Don't add text.
No music, just realistic real world sound.
```

Общий Vertex-гайд по видеопромптам советует обратное — никогда не писать «no»/«don't», а называть нежелательное существительным. **Это правило про заполнение поля `negativePrompt` у Veo, которого у Omni нет.** Для Omni пиши `No X`.

## 7. Тайминг

Синтаксис не требуется, работает естественный язык:

```text
After 3 seconds, a woman enters the scene.
At 5s the chorus starts in the background audio.
Every 2s cut to a new frame.
In a rapid fire sequence, every half a second (12 frames at 24fps) change the scene to a new location.
```

Либо таймкод-блоками:

```text
[0-3s] A person is walking
[3-6s] They stop and turn around
[6-10s] They start running
```

При расширении **`0s` означает начало продлённой части**, а не всего ролика.

## 8. Мета-промптинг

Omni реагирует на инструкции о том, *как генерировать*, а не только что:

```text
Consider micro-detail, expression and timing to create a very rich, detailed but entirely natural scene.
Be extremely detailed in your descriptions of characters and environments. Apply costume design principles to characters. Be very specific about the people, items and objects in the scene.
Include plenty of appropriate detail in the background elements to make the scene feel realistic and natural.
Make a rapid fire video that shows a different rare [thing] every 1s, upbeat music, include text to label the thing.
```

## 9. Жёсткие цифры — не угадывать

| Параметр | Значение |
|---|---|
| Длительность | `response_format.duration` — **строка**, целые секунды с `s`: `"3s"` … `"10s"`. Не int, не `duration_seconds`. |
| Суммарно после расширений | 40 с максимум, шагами по 10 с, только **в хвост** |
| Соотношение сторон | `16:9` (по умолчанию) или `9:16` — больше ничего |
| Разрешение | `360p` 640×360 · `720p` 1280×720 (по умолчанию) · `1080p` 1920×1080 · `4k` 3840×2160 |
| Природа 1080p/4k | **апскейл** рендера 720p, не нативный рендер |
| Частота кадров | 24 fps |
| Загружаемое видео для правки/расширения | ≤ 10 с |
| Референсные видео | ~3 с каждое, ~3 клипа; звук в них игнорируется |
| Язык | оценён английский; остальные могут работать непредсказуемо |
| Водяной знак | SynthID на каждом выходе, отключить нельзя |

Промпты пиши **по-английски**, даже если пользователь пишет по-русски. Неанглийские реплики бери в кавычки и предупреждай о разбросе качества.

## 10. Preflight — до дорогой генерации

Сверь бриф с §9 и назови несоответствия **до** запуска, а не после:

1. Запрошенная длительность попадает в 3–10 с? 15 секунд одной генерацией не существует — предложи 10 с плюс расширение, назвав цену.
2. Соотношение сторон 16:9 или 9:16? Квадрат и 4:3 недоступны — предложи кроп из 9:16 и уточни, что 1080p это апскейл 720p, поэтому под кроп часто честнее нативные 720p.
3. Не просят ли `temperature`, `negative_prompt`, `seed`, `personGeneration`? Их нет — скажи прямо, не молчи и не передавай.
4. Есть ли загружаемое видео? Тогда проверь регион (§ `gemini-omni-flash-failures.md`) — в EEA, Швейцарии, Великобритании и части штатов США загрузка видео для правки и расширения заблокирована.
5. Есть ли в промпте или референсах реальное узнаваемое лицо? Это детерминированный блок.
6. Нужен один кадр — стоит ли continuity lock?
7. Описан ли звук? Если нет — модель решит сама.

## 12. Порядок работы

1. **Определи режим** (§2) — от него зависят и companion-файл, и теги привязки медиа.
2. **Пройди preflight** (§10) и назови несоответствия до генерации.
3. **Собери промпт**: пять элементов + звук + тайминг + негативы. Один связный текст, не список тегов.
4. **Привяжи медиа явно**, если оно есть — `gemini-omni-flash-media.md`. Никогда не полагайся на позиционную удачу, когда изображений больше двух.
5. **Поставь continuity lock**, если многошотовость не нужна; для правок — `Keep everything else the same.`
6. **Черновики гони в 360p** — треть цены и до 60% быстрее. Победителя перегенерируй в целевом разрешении. Код, который отдаёшь пользователю, идёт **в целевом** разрешении, 360p упоминается как режим черновика; не выдавай черновой снипет как финальный вызов.
7. **Меняй одну переменную за итерацию.** Одновременная смена персонажа, локации, ракурса, стиля и погоды — названная причина дрейфа личности.
8. **Проверь результат по QA** (§13), затем сохрани файл в согласованную папку.

## 13. QA перед выдачей

Дополнительно к общему `qa-and-delivery.md`:

- **HTTP 200 не равно успех.** Целый класс отказов возвращает 200, `status: "completed"` и пустой выход. Проверяй наличие реального видеоконтента, а не код статуса.
- **Ответ быстрее 10 секунд — это отказ, а не быстрый рендер.** Успешные генерации 3-секундных клипов занимали 21.8–37.7 с; заблокированные возвращались за 2–9 с.
- Проверь первый кадр, переход и последний кадр; при интерполяции — что финальный кадр действительно соответствует последнему изображению.
- Проверь, что не появились незапрошенные монтажные склейки.
- Послушай звук: измеренный разброс громкости между генерациями — **26 dB**. Нормализуй каждый клип в посте, закладывай это в пайплайн.
- Проверь текст в кадре побуквенно: короткие английские строки на плоской фронтальной поверхности работают, упаковка, логотипы и мелкие вывески вырождаются в правдоподобную кашу.
- Проверь фактическое разрешение файла. `1080p` и `4k` — апскейл; если пользователь просил настоящий 4K, скажи это словами.

## 14. Частые ошибки

| Ошибка | Как правильно |
|---|---|
| Переписывать весь промпт ради одной мелкой правки | `previous_interaction_id` + короткая фраза правки + `Keep everything else the same.` Полная перезапись убивает консистентность сцены и персонажа. |
| Ждать буквального первого кадра от референсного изображения | Референс задаёт субъект и стиль, модель пересобирает сцену. Нужен буквальный стартовый кадр — только `<FIRST_FRAME>`. |
| Подавать закадровый голос, чтобы видео подстроилось под него | **Вход аудио в API не поддерживается.** Любой гайд, советующий «прикрепи свою озвучку», ошибается. Аудиовход есть только во Flow и приложении Gemini. |
| Называть реальное публичное лицо или загружать его внешность | Детерминированный блок. Вместо этого описывай признаки (возраст, телосложение, гардероб, волосы, выражение) либо сначала синтезируй лицо в Nano Banana и анимируй уже его. |
| Повторять отклонённый промпт без изменений | Блокировки детерминированы для идентичного payload. Меняй payload или не повторяй. |
| Просить текст упаковки, логотипы или мелкие вывески | Работают короткие английские строки в кавычках на плоской поверхности фронтально к камере; остальное вырождается в кашу. |
| Просить цепочку физических событий | Инструментированные тесты показывают, что последовательности «столкновение и остановка» проваливаются. Проси **одно** физическое событие. |
| Ставить `task="extend"` и одновременно передавать референсы | `task` отключает мультимодальные референсы и блокирует цепочку через `previous_interaction_id`. Предпочитай управление одним промптом. |
| Считать HTTP 200 успехом | Целый класс отказов возвращает 200, `completed` и пустой выход. Проверяй наличие реального видеоконтента. |

## 15. Диагностика

| Симптом | Причина | Действие |
